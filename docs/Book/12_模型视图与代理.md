# 第十二章　把数据和显示方式分开

[返回阅读地图](00_阅读地图与学习方法.md) · [上一章：列表表格与树](11_列表表格与树.md) · [下一章：文件配置与数据保存](13_文件配置与数据保存.md)

如果任务数据只保存在表格单元格里，要计算完成率就必须反过来读取界面；要换一种展示方式，又得复制一遍数据。随着功能增加，“控件里有什么”逐渐变成程序的唯一依据，维护就会变难。

模型视图的思路是：**数据模型负责提供和修改数据，视图负责展示，委托负责单元格的绘制和编辑，代理负责转换数据的展示方式。** 本章比较抽象，请先运行示例，再带着实际现象理解接口。

示例的数据保存在 `TaskModel._tasks` 中。`QTableView` 并不拥有另一套业务数据。数据流可以写成：

```text
Task 列表 ←→ TaskModel（源模型）←→ QSortFilterProxyModel（代理）←→ QTableView
                                                                      ↕
                                                       PriorityDelegate（编辑器）
```

## 2. 平面表格最基础的三个方法

`QAbstractTableModel` 是表格模型的基类。要显示只读数据，至少要正确实现 `rowCount()`、`columnCount()` 和 `data()`。基类已经帮助你实现了平面表格的很多结构逻辑。

`rowCount(parent)` 回答有多少行，`columnCount(parent)` 回答有多少列。参数 `parent` 是父模型索引，**不是 QObject 的所有者参数**。平面表格没有“单元格下面的子行”，所以当 `parent.isValid()` 为真时，示例返回 0。

`data(index, role)` 回答“这个位置、这种用途，需要什么数据”。`index.row()`、`index.column()` 是从 0 开始的坐标；`index.isValid()` 可以判断索引是否有效。`QModelIndex` 表示某个模型中的位置，它不是你业务数据的永久编号。

下面是示例里的概念性片段，依赖已经取得的 `task` 和 `index`，不能独立运行：

```python
values = (task.title, task.priority, task.completed)
if role == Qt.ItemDataRole.EditRole:
    return values[index.column()]
```

Qt 可能为了不同用途反复调用 `data()`，因此它应该快速、没有副作用。不要在这里下载网络内容、查询慢数据库或修改数据；否则滚动、重绘、排序都可能变慢甚至反复触发更新。

## 3. role 表示“同一个位置的不同用途”

| 角色 | 用途 | 本例如何使用 |
| --- | --- | --- |
| `DisplayRole` | 给用户看的内容 | 名称、优先级；完成列文本留空 |
| `EditRole` | 编辑器读取和写入的数据 | 字符串、整数、布尔值 |
| `CheckStateRole` | 复选框状态 | `Checked` 或 `Unchecked` |
| `UserRole` | 应用自定义用途 | 提供保留原始类型的排序值 |

未处理的角色返回 `None`，并不意味着出错，而是告诉 Qt“这个用途没有额外数据”。如果把所有角色都当作显示文本处理，背景色、复选框、编辑器等行为会出现异常。

表头通过 `headerData(section, orientation, role)` 提供：水平表头是字段名，垂直表头可以是从 1 开始的人类可读行号。这些行号同样不能作为任务编号。

## 4. 编辑需要三方配合

第一步，模型的 `flags(index)` 声明这个单元格支持什么。名称和优先级包含 `ItemIsEditable`；完成列包含 `ItemIsUserCheckable`。可选择、可用也是各自的标志，使用按位或 `|` 组合。

第二步，编辑器取得 `EditRole` 数据，让用户修改。通常内置委托能处理常见类型。本例为优先级增加 `PriorityDelegate`：`createEditor()` 创建 `QSpinBox`，`setEditorData()` 把当前值放入编辑器，`setModelData()` 把编辑器的新值提交给模型。

第三步，模型的 `setData(index, value, role)` 校验并更新真实数据。成功返回 `True`，拒绝修改返回 `False`。即使编辑器已经把数字范围限制为 1—5，模型依然要验证，因为测试代码、其他窗口或者未来的导入功能也可能直接调用模型。

`setData()` 修改成功后必须通知视图：

```python
# 示例片段：index 属于当前模型，内容已经验证并写入。
self.dataChanged.emit(index, index, [Qt.ItemDataRole.DisplayRole,
                                    Qt.ItemDataRole.EditRole,
                                    Qt.ItemDataRole.UserRole])
```

前两个索引表示变化区域的左上角和右下角，第三个参数列出变化的角色。实际完整示例还通知了 `CheckStateRole`。因为代理按照 `UserRole` 排序，我们也通知这个角色，确保编辑后排序能够及时反映新值。

拒绝修改不会自动弹出错误框；本例的空名称会恢复为旧值。正式项目可以通过额外的校验失败信号展示错误，不要让底层模型必须依赖 `QMessageBox`。

## 5. 插入、删除必须按协议通知

视图不知道 Python 列表何时变化。不能只调用 `.append()` 然后期待表格自动长出一行。正确的顺序是先通知“即将改变结构”，修改数据，再通知“结构改变结束”：

```python
# 示例片段：位于 TaskModel 的方法中。
row = len(self._tasks)
self.beginInsertRows(QModelIndex(), row, row)
self._tasks.append(Task(title))
self.endInsertRows()
```

`first` 和 `last` 是包含两端的行号范围；插入一行时相同。根层使用无效的 `QModelIndex()` 作为父索引。删除同理：`beginRemoveRows()` → 删除列表内容 → `endRemoveRows()`。输入验证和可能失败的准备操作尽量放在 `begin...` 之前，保证开始后的结构变更可以完整结束。

整份数据被替换时，可以使用 `beginResetModel()` / `endResetModel()`。但重置会让选择、索引等状态失效，不应为修改一个单元格就重置整个模型。也不要随便发 `layoutChanged` 来替代正确的插入删除通知。

## 6. 排序以后，视图行号不等于源行号

`QSortFilterProxyModel` 把源模型映射成另一种顺序或子集，通常不需要把源列表真正重新排列。本例通过 `setSourceModel()` 连接数据，`setSortRole(UserRole)` 指定比较的数据，视图启用排序后即可点击表头。

此时，视图选中的是**代理索引**。删除源数据前要先映射：

```python
# 来自完整示例的片段，依赖 self.table、self.proxy、self.model。
selected = self.table.selectionModel().selectedRows()
source_rows = {self.proxy.mapToSource(index).row() for index in selected}
for row in sorted(source_rows, reverse=True):
    self.model.removeRows(row, 1)
```

先把所有选中的代理索引转成源行号，再按降序删除。若直接用代理的 `row()` 去删源模型，排序后会删错任务；若边删除边映射旧索引，索引可能已经变化。反方向定位使用 `mapFromSource()`；过滤掉的源数据可能无法映射成有效的可见索引。

委托里的 `setModelData(editor, model, index)` 则应使用 Qt 传进来的 `model` 和 `index`。它们互相匹配；本例里是代理模型及代理索引，代理会把编辑转交源模型。不要在这里偷偷拿源模型配代理索引。

普通 `QModelIndex` 不适合长期保存。`QPersistentModelIndex` 能在模型正确发送结构通知时跟随部分变化，但删除或模型重置仍会让它失效；业务上要长久识别任务，仍应使用稳定编号。

## 7. 练习与自检

1. 增加“备注”列。验收：行列数量、表头、显示、编辑、校验、排序角色一起匹配，而不是只让界面多出一个标题。
2. 添加名称筛选框。查阅 `setFilterKeyColumn(0)`、`setFilterFixedString()`、`setFilterCaseSensitivity()`。验收：筛选状态下添加和删除仍作用于正确任务。
3. 写一个不创建窗口的小验证函数，构造 `TaskModel` 后尝试把优先级设置成 0、6、`"abc"` 和 3。前三项应返回 `False`，最后一项应成功。思考这为什么比只点击界面更容易检查规则。
4. 不看代码，解释一次编辑的顺序：编辑器取值 → 用户输入 → `setData()` 校验 → 修改数据 → `dataChanged` → 视图刷新。再解释代理插在哪一层。
