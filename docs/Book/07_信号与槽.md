# 第 7 章：信号与槽

> 前置知识：函数回调、控件读写、布局。目标：自己连接用户操作与业务行为，传递正确参数，定义自有信号，避免重复执行与循环更新。

信号槽是 PyQt6 的核心交互机制。前几章用它让按钮工作，这一章要从“会照着连”走到“能设计谁通知谁”。

## 7.1 信号表达发生了什么

`button.clicked` 表示按钮被点击，`line_edit.textChanged` 表示文本改变，`spin.valueChanged` 表示数值改变。发信号的对象只负责宣布变化，不需要知道所有接收者怎么处理。

```python
self.save_button.clicked.connect(self.save_document)
```

这段是局部连接代码，前提是控件和 `save_document` 方法已经存在。`connect()` 登记连接，`self.save_document` 是接收方法，`clicked` 是信号。以后用户点击，Qt 根据连接关系调用方法。

“槽”不意味着你必须使用某个特殊语法创建函数。在 PyQt6 中，普通函数、实例方法等 Python 可调用对象都可用于连接。`@pyqtSlot(...)` 是显式声明 Qt 槽的装饰器，有类型签名和元对象方面的用途，并不是让普通按钮回调生效的必要条件。

信号让发送方与接收方减少直接依赖。例如一个编辑对话框可以发出 `saved(str)`，主窗口决定怎样更新列表，而不用让对话框深入访问主窗口每个标签的内部名字。

## 7.2 参数从哪里来

先看三种信号：

| 信号 | 典型携带参数 | 接收方法示例 |
| --- | --- | --- |
| `QPushButton.clicked` | `checked: bool` | `def on_clicked(self, checked: bool)` |
| `QLineEdit.textChanged` | `text: str` | `def on_text(self, text: str)` |
| `QSpinBox.valueChanged` | `value: int` | `def on_value(self, value: int)` |
| `QPlainTextEdit.textChanged` | 无参数 | `def on_text(self)` 后自己读控件 |
| `QComboBox.currentIndexChanged` | `index: int` | `def on_index(self, index: int)` |

信号参数由发信号的对象提供。接收方法可以只接收它需要的前面部分参数，也可以像第一课那样完全不要额外参数。反过来，一个无参信号无法凭空满足要求两个必填参数的方法。

普通不可勾选按钮的 `clicked` 通常携带 `False`；启用 `setCheckable(True)` 后，`checked` 就反映按钮是否处于勾选状态。不要误把这个布尔值当成你的任务编号。

下面的片段需要放进包含 `name_edit`、`preview_label` 的窗口类：

```python
self.name_edit.textChanged.connect(self.update_preview)

def update_preview(self, text: str) -> None:
    self.preview_label.setText(f"预览：{text}")
```

这里 `text` 由信号传入，不需要接收方法再查一次输入框。如果回调要综合读取多个字段，如第二课更新提交按钮，也可以定义无额外参数的方法，在里面读各控件当前状态。

## 7.3 为什么 connect 里不加括号

```python
self.button.clicked.connect(self.save)    # 登记方法，等待点击
self.button.clicked.connect(self.save())  # 现在就调用，通常是错误
```

第二行先执行 `self.save()`，把其返回值交给 `connect()`。大多数保存方法返回 `None`，所以会出现类型错误；即便返回的是可调用对象，行为也已和第一行不同。遇到“还没点击就自动执行”，第一步就检查这里。

连接通常放在构造阶段，只做一次。不要在每次 `refresh()` 时又调用一遍 `connect()`，否则同一处理方法可能每次点击执行多次。确实需要解绑时，使用 `signal.disconnect(slot)` 断开指定连接；不确定是否存在连接时要先理清状态，避免用空 `except` 把设计错误藏起来。

同一信号可以通知多个接收者，一个接收者也可以接多个信号。核心业务应保持清楚的顺序依赖：如果“保存成功后才能显示成功”，就把显示放在成功流程中，不要依赖多个不清晰连接拼出隐含顺序。

## 7.4 lambda：给回调补充你自己的参数

当多个按钮调用同一个方法但传入不同标识时，lambda 很方便：

```python
self.open_button.clicked.connect(
    lambda checked=False: self.open_page("settings")
)
```

`lambda` 定义一个短函数，点击时才执行右边的方法。`checked=False` 接收并忽略按钮信号的布尔参数，真正的业务参数是 `"settings"`。

循环创建按钮时还要注意 Python 闭包的“晚绑定”：

```python
for page_id, button in page_buttons:
    button.clicked.connect(
        lambda checked=False, selected_id=page_id: self.open_page(selected_id)
    )
```

这是概念片段，`page_buttons` 是事先准备好的 `(页面标识, 按钮)` 列表。默认参数 `selected_id=page_id` 会在这一轮创建函数时保存当前标识。若只写 `lambda: self.open_page(page_id)`，所有回调可能在点击时都读到循环最后的 `page_id`。

也不要写 `lambda selected_id=page_id: ...` 来连接 `clicked`，因为信号传入的布尔参数可能覆盖你的默认值。先留一个 `checked` 位置，含义就清楚了。

lambda 适合短小适配。校验、文件操作、多步状态更新应写成有名字的方法，方便调试和复用。

## 7.5 自定义信号：让数据变化主动通知界面

完整示例：[第三课_信号练习.py](示例代码/第三课_信号练习.py)。运行命令：

```powershell
.\docs\Book\.venv\Scripts\python.exe .\docs\Book\示例代码\第三课_信号练习.py
```

窗口包含数字输入框、滑块、计数标签、“加一”和“归零”。操作其中一个，其他显示同步变化。真正的计数保存在 `Counter` 对象中，不由标签文字反向推导。

这是完整示例中的类定义摘录，仍需要外部导入，不能单独当程序运行：

```python
class Counter(QObject):
    value_changed = pyqtSignal(int)

    def __init__(self, parent: QObject | None = None) -> None:
        super().__init__(parent)
        self._value = 0

    def value(self) -> int:
        return self._value

    @pyqtSlot(int)
    def set_value(self, value: int) -> None:
        value = max(0, min(value, 100))
        if value == self._value:
            return
        self._value = value
        self.value_changed.emit(value)
```

`QObject`、`pyqtSignal`、`pyqtSlot` 都从 `PyQt6.QtCore` 导入。自定义信号声明在 QObject 子类的**类体**，而不是在 `__init__` 里临时写 `self.value_changed = pyqtSignal(int)`。

`pyqtSignal(int)` 声明信号携带一个整数。发出通知使用 `self.value_changed.emit(value)`。这不是调用所有接收者的名字，而是请 Qt 按已登记的连接发送通知。

`_value` 前面的单下划线表达“这是内部实现”的约定，不是 Python 强制的私有访问限制。`value()` 提供读接口，`set_value()` 统一检查范围和发信号。这样调用方不应直接写 `_value`，否则会绕开通知。

`@pyqtSlot(int)` 声明该方法作为接受一个整数的 Qt 槽。去掉它后，这个单线程示例通常也能工作，但保留它有助于明确接口；涉及线程时，接收对象及槽的线程上下文尤为重要，第 15 章再深入。

## 7.6 看懂数据流与循环保护

示例连接关系是：

```text
数字框 valueChanged ─┐
滑块 valueChanged ───┼→ Counter.set_value → 更新 _value → value_changed
按钮的处理方法 ──────┘                                      ├→ 数字框 setValue
                                                          ├→ 滑块 setValue
                                                          └→ 标签显示方法
```

既然模型更新数字框，数字框变化又更新模型，为什么不会无限循环？因为有两层保护：Qt 控件在数值没有实际变化时通常不再次发出 `valueChanged`；模型也明确检查新值与旧值，相同就返回。

假设滑块从 0 变成 7：滑块发信号 → 模型存 7 → 模型发信号 → 数字框改成 7 并发信号 → 模型发现已经是 7，立即返回。最后标签显示 7，调用链结束。

注意模型先修改 `_value`，再 `emit()`。如果通知时数据还没更新，接收方读取模型就可能看到旧状态。变化通知应与实际数据状态保持一致。

窗口创建时，模型与控件初始值都是 0，不会因为“本来就是 0”自动发变化信号，所以示例主动调用 `show_value(self.counter.value())` 做首次显示。初始化界面不应依赖一个实际上没有发生的变化。

## 7.7 程序改值也可能发信号

`setText()`、`setValue()`、`setChecked()` 等方法在状态改变时通常会发相应的变化信号。它们不只服务于鼠标和键盘操作。这对自动同步很有用，但批量载入配置时可能导致不必要的保存或计算。

可以让处理逻辑识别“加载中”，或者在明确的局部范围使用 `QSignalBlocker`：

```python
from PyQt6.QtCore import QSignalBlocker

with QSignalBlocker(self.age_spin):
    self.age_spin.setValue(18)
self.update_summary()
```

这是在已存在的窗口方法里的片段。blocker 暂时阻止**这个对象**发信号，离开范围后恢复原先阻止状态。被阻止的信号不会在解除后自动补发，所以末尾明确刷新一次汇总。它也不会阻止其他对象的信号，更不能用它替代线程同步锁。

先写明你希望哪一次变化触发哪件事，再决定是否阻止信号。不要一遇到循环就把所有信号关掉，否则正常更新也可能丢失。

## 7.8 信号不等于后台线程

在本章的同线程默认连接中，信号发出后，接收处理通常在当前调用过程中执行。如果某个槽要运行 10 秒，发送方也会等它执行，界面会受阻。

跨线程连接可能使用排队方式，由接收对象所属线程的事件循环稍后执行。这依赖连接类型、对象所属线程等条件，不能简化成“所有信号都是异步”。本章先掌握单线程数据流；耗时工作不要仅靠换成信号就以为已经放到后台。

信号传入的数据也不应默认当作自动深拷贝。尤其使用 `pyqtSignal(object)` 传递 Python 可变对象时，要明确谁可以继续修改它；线程章节会继续讨论所有权和数据快照。

## 7.9 本章练习与自检

1. 给第三课增加“减一”按钮，只调用模型的 `set_value()`，验证最小值仍是 0。
2. 增加第二个标签，显示“低于 50”或“不低于 50”，接收同一个 `value_changed`，不要让第一个标签调用第二个标签。
3. 在模型中增加打印，分别将数值设为 7、再设为 7，解释为什么第二次不发变化信号。
4. 创建三个按钮，分别设为 10、50、90，使用循环连接，验证不会全部变成 90，也不会把 `checked` 布尔值误当数值。
5. 合上示例，独立写一个温度设置窗口：一个数字输入框、一个滑块、一个文字显示，共享同一个值；先画数据流，再写代码，最后验证重复设置相同值不会形成循环。

自检：能否说清信号由谁发、参数从哪来、槽何时执行？能否解释为什么自定义信号写在类体、为什么模型先更新再通知？能否从一次操作追踪到所有被更新的对象？这些能力是继续学习多窗口通信和后台任务的基础。
