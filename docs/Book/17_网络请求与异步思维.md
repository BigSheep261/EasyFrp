# 第 17 章：网络请求与异步思维——发出请求，然后继续响应用户

[上一章：外部进程与实时日志](16_外部进程与实时日志.md) · [阅读地图](00_阅读地图与学习方法.md) · [下一章：项目结构与分层设计](18_项目结构与分层设计.md)

本章目标：理解网络请求的整个生命周期，在 Qt 事件循环中发送请求，正确处理超时、取消、HTTP 状态和资源释放。网络并不总能成功，错误路径就是正常开发内容的一部分。

## 1. 从“调用一个函数”转向“管理一段过程”

普通函数常写成 `result = calculate()`，调用返回时结果已经得到。网络请求需要经过地址解析、建立连接、TLS 握手、等待服务端、接收数据等步骤，耗时从毫秒到数十秒都有可能。

如果在按钮槽里直接调用同步的 `requests.get()`，界面会等待它返回，和上一章的长循环一样卡住。设置超时只是限制最多卡多久，不会让它自动异步。

Qt 提供 `QNetworkAccessManager`：`get(request)` 很快返回一个 `QNetworkReply`，随后通过信号报告进展和结束。此时拿到的是“这次请求的句柄”，还不是网页内容。

可以把过程理解为：界面发出请求，记录自己正在等待的 reply；事件循环继续工作；数据到达时执行短回调；请求结束时读取结果、恢复按钮并释放对象。这个思路也适用于 `QProcess`、定时器和很多设备通信接口。

## 2. 三个核心对象的职责

| 对象 | 它代表什么 | 应如何持有 |
| --- | --- | --- |
| `QNetworkAccessManager` | 网络会话管理者，负责请求和连接复用 | 通常作为窗口或服务对象的成员长期存在 |
| `QNetworkRequest` | 地址、请求头、重定向策略等请求设置 | 构造后交给 manager，可作为局部变量 |
| `QNetworkReply` | 一次请求的异步状态与响应数据 | 保存引用，结束后调用 `deleteLater()` |

本例在主线程创建并使用这三个对象。manager 的异步 API 已接入 Qt 事件循环，不需要额外工作线程。响应结束后若要处理几十兆 JSON、解压大型文件或执行重计算，那是另外一个耗时任务，需要分块或交给后台处理。

本例一次只允许一个请求，以避免最初就引入多个并发 reply 的管理。它限制总请求时长为十秒、最多保存 128 KiB 响应，显示 HTTP 状态和文本结果，并提供取消按钮。

## 4. 按请求生命周期拆解

第一步，验证地址。`QUrl` 可以解析许多种 URL，本例额外限定协议为 HTTP 或 HTTPS，并要求主机名存在。地址格式正确，不代表目标存在或一定可访问。

第二步，清空上次状态，禁用请求按钮，创建请求：

```python
request = QNetworkRequest(url)
self._reply = self.manager.get(request)
self._reply.readyRead.connect(self.read_body)
self._reply.finished.connect(self.request_finished)
self.timer.start(10000)
```

`readyRead` 时读取当前可用字节并加入 `bytearray`。这里只保存数据，不对每个分片独立解码，所以不会把一个 UTF-8 中文字符切坏。结束后统一解码。若要做无限日志流，应采用上一章的增量解码方案。

第三步，`finished` 时停止计时器、读取最后的数据、检查状态。无论成功、网络错误或取消，都要进入收尾过程，清空 `self._reply` 并调用 `reply.deleteLater()`。不要只在成功路径释放 reply。

Qt 不会因为 `finished` 发出就自动保证你的 reply 已经删除。manager 的父子关系提供最终兜底，及时释放每次请求对象仍是长期运行程序需要做到的事。

## 5. HTTP 状态与网络错误是两层信息

`reply.error()` 返回 Qt 的网络错误枚举；`reply.errorString()` 给出可读说明。域名不存在、连接失败、TLS 证书问题都会体现为网络层或协议层错误。

`reply.attribute(HttpStatusCodeAttribute)` 提取服务器返回的 HTTP 状态，例如 200、404 或 500。根本没有收到 HTTP 响应时，它可能是 `None`。某些 HTTP 失败状态也会映射成 Qt 的错误枚举，因此它们不是完全互斥的分类。

处理时同时记录两类信息，能更准确地解释“没连上服务器”还是“服务器已经回答，但拒绝或处理失败”。`finished` 只表示过程结束，**不表示请求成功**。

本例接受 200 至 299 为 HTTP 成功状态。真实接口还需验证内容类型、JSON 格式及业务字段；HTTP 200 中仍可能包含业务错误。

若接口约定返回 JSON，可在成功分支用 `json.loads(bytes_data)` 解析，并捕获 `(UnicodeDecodeError, json.JSONDecodeError)`：前者表示字节编码无法解读，后者表示文本不符合 JSON 语法。对外部数据还应限制响应大小与可接受结构，必要时将解析器的 `RecursionError` 翻译为格式错误。随后检查字段是否存在、类型是否正确，而不是直接层层下标访问。

## 6. 超时、取消与重定向

示例用单次 `QTimer` 限制整段请求最长十秒。计时器到时先设 `_timed_out`，再调用 `reply.abort()`。用户取消时先设 `_cancelled`，再 abort。这样即使二者最终都表现为操作取消错误，界面仍能解释真实原因。

`abort()` 是终止当前请求，之后仍通过结束处理释放 reply。关闭窗口时也会停止计时器并 abort，避免把请求继续留在后台。

网络库里“超时”可能有不同含义：整个请求截止时间、连接时间上限、两次收到数据之间的空闲时间上限。`QNetworkRequest.setTransferTimeout(milliseconds)` 提供的传输超时侧重无数据传输的间隔；本例的总时长计时器语义更直观，二者不要混淆。

示例明确使用 `NoLessSafeRedirectPolicy`，允许符合策略的重定向，避免 HTTPS 被悄悄降级到 HTTP。不要为了绕过连接错误随手调用 `ignoreSslErrors()`；先检查系统时间、证书链、代理配置和服务端证书。

## 7. 不依赖互联网也能练习

打开另一个 PowerShell，在项目根目录执行：

```powershell
.\docs\Book\.venv\Scripts\python.exe -m http.server 8765 --bind 127.0.0.1 --directory .\docs\Book
```

这是仅绑定本机回环地址的教学服务器。保持这个终端运行，把示例窗口中的地址改为 `http://127.0.0.1:8765/`。你应看到状态 200 和目录网页。请求 `/不存在的文件.txt` 可观察 404；按终端的 `Ctrl+C` 停止服务器，再请求可观察连接失败。

这几种测试可以离线重复，不依赖第三方服务。验证超时需要一个延迟响应的测试服务器或测试替身；不要假定某个外部地址永远足够慢。后面的测试章会讲“可控制的外部依赖”为什么重要。

## 8. 常用 API

| API | 输入 | 返回值或作用 |
| --- | --- | --- |
| `QUrl(text)` | 地址字符串 | URL 对象，`isValid()` 返回格式检查结果 |
| `manager.get(request)` | `QNetworkRequest` | 立即返回 `QNetworkReply` |
| `manager.post(request, data)` | 请求及 `QByteArray` 或兼容字节参数 | 返回 reply；服务端格式要求决定 data 内容 |
| `reply.readAll()` | 无 | 读取当前可用数据的 `QByteArray`，不是等待全部完成 |
| `reply.attribute(name)` | 属性枚举 | 对应属性值，未获得时可能为空 |
| `reply.abort()` | 无 | 取消请求，触发后续错误和结束处理 |
| `request.setRawHeader(name, value)` | 字节形式的名称和值 | 设置请求头，例如内容类型 |
| `reply.deleteLater()` | 无 | 安排响应对象释放 |
