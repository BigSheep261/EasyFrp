# 第 2 章：认识 Qt 与 PyQt6

> 前置知识：第 1 章中的类、继承和回调。目标：能画出桌面程序的基本组成，知道从哪个模块找类，并解释“程序如何等待用户操作”。

## 2.1 先分清四个名字

**Python** 是你写程序使用的语言。**Qt** 是主要用 C++ 开发的应用框架，提供窗口、控件、事件、网络、数据库、绘图等能力。**PyQt6** 是 Qt 6 的 Python 绑定，让 Python 能调用 Qt。**你的应用** 则把这些能力组合起来，完成自己的业务。

可以把调用过程理解为：你写 `label.setText("完成")`，PyQt6 把 Python 调用传到 Qt 对象，Qt 更新控件，再由系统和图形系统完成屏幕上的显示。你不必从零实现文字绘制和鼠标命中判断。

PySide6 也是 Qt 6 的 Python 绑定，来自 Qt 官方体系，和 PyQt6 很像，但包名、自定义信号写法及部分行为不同。学习期间统一使用 PyQt6，不要在同一个控件树里混用两种绑定。PyQt5 则绑定 Qt 5；旧教程中的 `exec_()`、`Qt.AlignCenter` 等写法，不能原样当作本书的 Qt 6 写法。

PyQt6 使用 GPL v3 与商业许可双重许可，并非 LGPL；Qt 本身又有自己的许可和模块差异。做练习时先专注学习，准备分发实际产品时，再核对 [Riverbank 的许可说明](https://www.riverbankcomputing.com/software/pyqt/)。安装包免费可下载，并不等于任何分发方式都没有许可条件。

## 2.2 一个窗口程序由哪些部分组成

假设我们做一个任务清单工具：上面有输入框，中间有任务列表，下面有“添加”按钮。至少包含以下部分：

| 部分 | 负责什么 | 例子 |
| --- | --- | --- |
| 应用对象 | 管理 GUI 应用与事件循环 | `QApplication` |
| 窗口与控件 | 展示内容、接收输入 | `QWidget`、`QLineEdit`、`QPushButton` |
| 布局 | 根据可用空间排列控件 | `QVBoxLayout`、`QFormLayout` |
| 交互连接 | 用户操作后触发相应处理 | `clicked.connect(...)` |
| 应用数据和规则 | 保存任务、检查标题、计算状态 | Python 类、列表、函数 |
| 外部资源 | 保存文件、访问网络等 | `Path`、QtNetwork、数据库 |

按钮上写“添加”，不会自动知道要添加什么。你必须读取输入、检查规则、更新数据，再更新显示。界面只是应用的一部分，能做出漂亮窗口与能做出可靠软件之间，还隔着数据管理、错误处理、结构设计和交付。

## 2.3 控制台程序与 GUI 程序的执行方式

控制台练习常按你写好的顺序执行：输入 → 计算 → 打印 → 结束。GUI 中，用户可能先缩放窗口，再点击按钮，再修改文本；开发者无法预知操作顺序。

因此 GUI 使用**事件循环**。简化过程是：

```text
创建应用和窗口
       ↓
进入事件循环
       ↓
等待/获取事件 → 分发给目标对象 → 调用相关处理 → 回到事件循环
       ↑_________________________________________________|
```

事件包括鼠标、键盘、窗口关闭、计时器到期和绘制请求等。循环由 Qt 管理，你通常只需调用 `app.exec()`，不用自己写 `while True` 来检查按钮。

事件循环需要及时拿回控制权。如果按钮的处理方法里执行 `time.sleep(10)` 或耗时计算，主线程会忙着等待或计算，无法及时处理重绘和输入，窗口看起来就“卡死”。这不是按钮坏了，而是事件处理被堵住了。以后通过 `QTimer` 做分时操作，通过工作线程处理适合放到后台的耗时任务。

`show()` 表示请求显示窗口，真正的绘制仍需要事件循环参与。不要把 `app.exec()` 理解为“一次性把所有函数执行完”，它通常会一直运行到应用退出。

## 2.4 模块是工具箱，类是工具的类型

模块可以理解为按用途分类的工具箱。`from PyQt6.QtWidgets import QPushButton` 中，`QtWidgets` 是模块，`QPushButton` 是类，`QPushButton("保存")` 是创建一个按钮。

第一阶段最常见的是下面三个模块：

| 模块 | 主要职责 | 先认识的类或名字 |
| --- | --- | --- |
| `QtCore` | 对象基础、信号、事件、时间、线程、模型基础 | `QObject`、`Qt`、`QTimer`、`QThread`、`pyqtSignal` |
| `QtGui` | 绘图、图像、字体、图标、部分交互基础 | `QColor`、`QFont`、`QIcon`、`QPainter`、`QAction` |
| `QtWidgets` | 传统桌面窗口、控件、布局和对话框 | `QApplication`、`QWidget`、`QMainWindow`、`QLabel`、`QVBoxLayout` |

模块名不是完全按日常汉语分类的。例如 `QAction` 虽然会用在菜单和工具栏中，Qt 6 的导入位置是 `PyQt6.QtGui`，不是 `QtWidgets`。`QApplication` 则在 `QtWidgets`；只做无界面 Qt 服务时常用的 `QCoreApplication` 在 `QtCore`。

等你确实需要某项能力时，再选择对应模块：

| 需要做的事 | 相关模块/类 | 学习前提 |
| --- | --- | --- |
| HTTP 请求、套接字通信 | `QtNetwork` / `QNetworkAccessManager` | 信号、异步结果、错误处理 |
| SQL 数据库访问 | `QtSql` / `QSqlDatabase`、`QSqlQuery` | SQL 与连接生命周期 |
| 音视频播放与采集 | `QtMultimedia` | 异步状态与系统媒体环境 |
| 打印与打印预览 | `QtPrintSupport` | 文档布局或绘图 |
| 显示 SVG 图形 | `QtSvg`、`QtSvgWidgets` | 图像资源与控件基础 |
| PDF 文档 | `QtPdf`、`QtPdfWidgets`（视发行包支持） | 文档与视图 |
| 嵌入完整网页 | `QtWebEngineCore`、`QtWebEngineWidgets` | 通常还要安装 `PyQt6-WebEngine` |
| QML / Qt Quick 界面 | `QtQml`、`QtQuick` | QML 与另一套界面组织方式 |
| 自动化界面测试 | `QtTest` | 可测试的程序结构 |

这张表是选择方向的地图，不要求现在背下来。Qt 6 包含的模块、PyQt6 当前版本提供的绑定，以及本机 wheel 实际安装了什么，可能不完全相同。遇到缺模块，先查安装包和版本，不要仅凭 Qt C++ 文档猜测 Python 环境一定具备它。

本书先学 Qt Widgets。这套控件体系适合表单、配置工具、管理工具等传统桌面应用。QML/Qt Quick 更强调声明式界面和动态视觉效果，需要单独学习，不能把两套 API 当成同一种写法混着套用。

## 2.5 四个必须分清的词

**函数**是一段可调用的代码，例如 Python 的 `len(text)`。**方法**是关联到类或对象的函数，例如 `label.setText(text)`。调用方法时，你主动要求某个对象做事。

**信号**表示某个对象发生了某件事，例如按钮发出 `clicked`，输入框发出 `textChanged(str)`。信号本身不是你的业务逻辑；它可以连接零个、一个或多个接收方法。**槽**就是接收信号的处理入口，在 PyQt6 中可以是普通 Python 可调用对象，也可以是 `@pyqtSlot` 声明的方法。

**事件**是 Qt 分发给对象的一次消息，例如按键事件、关闭事件。对象通过 `keyPressEvent`、`closeEvent` 等方法处理它。按钮通常先收到较底层的鼠标事件，再根据自身逻辑决定发出 `clicked` 信号。

| 表达式 | 你正在做什么 |
| --- | --- |
| `label.setText("完成")` | 主动调用一个方法 |
| `button.clicked.connect(self.save)` | 登记一个信号接收者 |
| `def save(self): ...` | 定义要执行的 Python 方法 |
| `def closeEvent(self, event): ...` | 重写 Qt 提供的事件处理入口 |

一般业务交互优先使用已有信号。只有需要干预底层输入、绘制或关闭行为时，再考虑事件重写。不要为了捕获按钮点击就先去实现 `mousePressEvent`。

## 2.6 与 MFC 的有限类比

| 你可能见过的 MFC 概念 | 在 Qt 中可借助理解的概念 | 类比的边界 |
| --- | --- | --- |
| 应用对象、消息循环 | `QApplication`、事件循环 | 不需要照搬 MFC 启动代码 |
| `CWnd` 及窗口派生类 | `QWidget` 及其子类 | Qt 对象不都对应一个系统原生窗口句柄 |
| 消息映射、处理函数 | 信号槽与事件处理 | 信号不是 Windows 消息编号，跨平台且可自定义 |
| 资源编辑器中的对话框布局 | Qt Designer 的 `.ui` 文件 | Qt 更依赖布局管理器适应空间和字体 |
| 文档/视图思路 | 数据与界面分离、模型/视图 | Qt 的 model/view 有自己的索引与通知协议 |

MFC 经验能帮助你接受“框架在适当时候调用我的方法”，但不要试图把所有 Qt 操作翻译成 Windows 消息发送。先按 Qt 的对象、信号和布局模型学习，会更直接。

## 2.7 如何面对成千上万的 API

目标不是背完 Qt，而是能回答：我要解决什么问题？谁负责它？对象怎样创建？什么方法改变状态？什么方法读取状态？完成或失败时通过什么信号告诉我？对象活多久？

查资料时，先看 [PyQt6 文档](https://www.riverbankcomputing.com/static/Docs/PyQt6/)，再结合 [Qt 6 类参考](https://doc.qt.io/qt-6/classes.html)理解语义。Qt 网站不少示例使用 C++，需要把类型和语法转换为 Python；以本机 PyQt6 的可用 API 为准。后面的模块手册会继续训练这种查阅方式。

## 2.8 本章练习与自检

1. 画出一个“记账工具”的窗口、控件、数据、存储四部分，各写两项职责。
2. 在不查表的情况下，说出创建按钮、设置字体、启动计时器分别优先去哪一个模块。
3. 解释 `clicked.connect(...)` 为什么不等于“现在点击按钮”。
4. 用自己的话向另一位初学者解释：为什么在按钮回调里睡眠会导致窗口没有响应？
5. 打开 `QLineEdit` 的 Qt 文档，找出一个读值方法、一个改值方法和一个变化信号，只记录用途，不复制全部接口。

自检：你应能区分 Qt、PyQt6、QtWidgets；能分清信号与事件；知道要使用事件循环，而不是自行轮询按钮。下一章把这些概念放进可运行程序。
