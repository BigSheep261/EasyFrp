# 第十三章　让数据安全地留到下一次启动

[返回阅读地图](00_阅读地图与学习方法.md) · [上一章：模型视图与代理](12_模型视图与代理.md) · [下一章：样式资源与界面设计](14_样式资源与界面设计.md)

界面里的文字只是内存中的状态，程序退出后不会自动保存。完成一个可长期使用的桌面应用，需要回答三个问题：保存什么、保存到哪里、失败时怎么办。本章通过一个简单文本编辑器，把这三个问题串成完整流程。

先区分三种内容：用户主动打开和保存的文档；程序自己的结构化业务数据；窗口大小、最近目录等偏好设置。它们可以使用不同的格式和位置，不必塞进同一个文件。

## 1. 运行完整文件示例

代码：[第六课：设置与文件](示例代码/第六课_设置与文件.py)。从项目根目录执行：

```powershell
.\docs\Book\.venv\Scripts\python.exe .\docs\Book\示例代码\第六课_设置与文件.py
```

输入几行中文，观察标题中的星号；保存为文本文件；修改内容后关闭，分别试试取消、放弃和保存；重新启动，检查窗口位置是否恢复。首次运行会在操作系统提供的应用数据位置创建本课目录，并用 `QSettings` 保存少量偏好设置；文本保存位置由你在对话框中选择。

它是教学用的小文本编辑器：按 UTF-8 处理普通文本，读写发生在主线程，适合小文件。很大的文件可能让界面短暂失去响应，后台任务的组织方法在第十五章学习。

## 2. 选择路径不等于已经读写文件

`QFileDialog.getOpenFileName()` 返回 `(filename, selected_filter)`。第一个是用户选中的路径，第二个是所选过滤器描述，不是文件内容。用户取消时路径通常为空字符串，因此第一步应检查：

```python
# 来自示例的片段，依赖 self 及已经导入的 QFileDialog。
filename, _ = QFileDialog.getOpenFileName(
    self, "打开 UTF-8 文本", self.last_directory,
    "文本文件 (*.txt);;所有文件 (*)"
)
if not filename:
    return
```

不同过滤器之间用 `;;` 分隔。过滤器帮助用户查找文件，并不会验证文件内容一定正确。

读取文本时，本例使用 `Path(filename).read_text(encoding="utf-8")`。明确编码可以避免同一份中文文本在不同电脑上出现不同结果。系统拒绝访问、文件被移走等情况会产生 `OSError`；字节不符合 UTF-8 会产生解码异常。示例捕获这些预期错误并展示原因，而不是让程序直接退出。

不要为了“任何文件都能打开”随便使用 `errors="ignore"`：它可能悄悄丢掉文字。需要兼容其他编码时，应给用户清楚的编码选择和失败反馈。

示例先让用户决定如何处理旧文档的未保存修改，再把新文件读入一个局部变量；只有读取成功才替换编辑器内容。这样读取失败时，原来的文档仍留在界面中。先处理保存也能避免一个细节错误：用户选择重新打开当前文件并要求先保存时，应该读到刚保存的版本，而不是预先读取的旧内容。

## 3. 保存函数的 bool 返回值是整个流程的基础

第六课中，`save_file()`、`save_as()`、`write_file()` 都返回 `bool`。`True` 表示确实保存成功；`False` 包括用户取消选路径以及写入失败。这样上层流程可以统一判断：

```python
# 概念片段：用户在未保存提示框中选择了“保存”。
if result == QMessageBox.StandardButton.Save:
    return self.save_file()
```

假设用户关闭窗口，选择“保存”，然后又取消保存路径选择，此时 `save_file()` 返回 `False`，`closeEvent()` 应调用 `event.ignore()`。如果你只判断用户曾经点击过“保存”，就可能在没有真正落盘时关闭窗口。

编辑器文档的 `isModified()` 告诉我们是否存在修改，`modificationChanged(bool)` 在修改状态变化时通知界面。成功打开或保存后，才把状态设置成未修改。标题星号只是该状态的显示方式，不能反过来通过检查标题字符串判断是否需要保存。

## 4. 用 QSaveFile 降低覆盖文件的风险

直接 `open(path, "w")` 会截断原文件。如果写入中途失败，原有内容可能丢失。`QSaveFile` 通常先写临时文件，`commit()` 成功后再替换目标文件，适合配置和文档保存。

完整示例检查了三个阶段：

1. `open(QIODevice.OpenModeFlag.WriteOnly)` 是否返回 `True`。
2. `write(data)` 返回的字节数是否等于待写入的长度。
3. `commit()` 是否返回 `True`。

这里 `data = text.encode("utf-8")` 得到字节。字符数量和 UTF-8 字节数量不相同，所以写入长度必须与 `len(data)` 比较，不能与原字符串长度比较。

写入失败调用 `cancelWriting()`，并通过 `errorString()` 解释失败；只有提交成功才更新当前文件路径、清除修改标记。示例没有启用直接写入回退，因为回退会改变临时文件替换的保护方式。

这种机制不能解决所有场景，例如两个程序同时编辑同一文档、远程文件系统特殊行为、磁盘硬件故障。产品要处理并发修改时，还需考虑修改时间检查、版本号或文件锁；不要把一次 `commit()` 当成整个数据系统的事务设计。

## 5. 设置放 QSettings，位置问 QStandardPaths

`QSettings` 适合窗口位置、主题偏好、最近目录等少量键值。默认构造函数使用应用身份，所以顺序很重要：

```python
# 示例片段：app 已经创建，但尚未构造 QSettings。
app.setOrganizationName("PyQt6Learning")
app.setApplicationName("TextFileLesson")
settings = QSettings()
settings.setValue("editor/font_size", 12)
font_size = settings.value("editor/font_size", 12, type=int)
```

读值提供默认值，让第一次启动也能工作；指定 `type`，让自己知道读到的是什么类型。默认存储后端依平台而定，例如 Windows 通常使用注册表，因此不要假定 `QSettings()` 一定生成项目目录里的 ini 文件。需要明确文件格式时，可以使用指定路径与 `QSettings.Format.IniFormat` 的构造方式。

写入设置后调用 `sync()` 可以要求同步，随后用 `status()` 检查结果。`QSettings` 不是用于保存密码的安全保险箱，也不是业务数据库；普通偏好设置放在这里很合适，大量结构化数据应另选方式。

应用自己的数据目录使用：

```python
# 片段：需要先设置应用名称，并导入 QStandardPaths。
location = QStandardPaths.writableLocation(
    QStandardPaths.StandardLocation.AppDataLocation
)
```

它返回平台合适的路径字符串，但目录不一定已经存在，也不保证创建或写入一定成功；示例检查空路径并调用 `mkdir(..., exist_ok=True)`，同时处理异常。当前工作目录、代码目录和用户数据目录是不同概念：程序从快捷方式启动时，工作目录可能变化；打包程序所在目录也可能不可写。

## 6. JSON 和 SQLite 应该怎样选择

纯文本适合笔记，JSON 适合规模不大、整体读取和保存的结构化数据，SQLite 适合需要查询、关联关系、事务和更多记录的本地数据。[第十八章](18_项目结构与分层设计.md)及综合实战会继续运用分层思路；这里先建立格式意识。

例如任务数据可以是：

```json
{
  "版本": 1,
  "任务": [
    {"编号": 101, "名称": "完成练习", "优先级": 3, "已完成": false}
  ]
}
```

Python 写 JSON 时使用 `json.dumps(data, ensure_ascii=False, indent=2)` 便于阅读中文，再按 UTF-8 保存；读取使用 `json.loads(text)`。读取成功不代表结构有效，还应检查顶层类型、必填字段、字段类型、取值范围和版本号。`json.JSONDecodeError` 负责语法错误，业务结构错误则需要自己校验。

不要把整个窗口对象序列化，也不要把 `QModelIndex` 当成持久数据。保存的是任务编号、名称、状态等业务内容，窗口启动后再根据数据创建界面。恢复外部提供的 `pickle` 数据可能执行代码，因此它不适合作为导入任意用户文件的通用格式。

## 7. API 与练习

| API | 返回值 | 应处理的分支 |
| --- | --- | --- |
| `getOpenFileName()` / `getSaveFileName()` | 路径、过滤器组成的元组 | 路径为空表示取消 |
| `QSaveFile.write(bytes)` | 写入字节数，错误时可能为负值 | 检查是否完整写入 |
| `QSaveFile.commit()` | `bool` | 成功后才清除未保存状态 |
| `QSettings.value(key, default, type=...)` | 设置值或默认值 | 第一次启动、类型转换问题 |
| `QSettings.status()` | 状态枚举 | 同步后判断写入是否失败 |
| `writableLocation(type)` | 路径字符串 | 空路径、目录不存在、创建失败 |

1. 给第六课增加“新建”操作。验收：当前有未保存内容时，同样经过保存、放弃、取消流程。
2. 保存和恢复编辑器字号。验收：首次启动有合理默认值；保存的字号不在允许范围时使用默认值。
3. 将第五课任务列表转成带版本号的 JSON，再从 JSON 恢复。把格式错误和字段错误分开报告；不要直接访问或保存表格控件内部状态。
4. 建立自己的手工验证表，至少包含取消打开、取消另存为、中文路径、无权限位置、非 UTF-8 文件和关闭时保存失败。能解释每种情况下旧文档为何不会丢失，才算掌握文件流程。

查阅入口：[QFileDialog](https://doc.qt.io/qt-6/qfiledialog.html)、[QSaveFile](https://doc.qt.io/qt-6/qsavefile.html)、[QSettings](https://doc.qt.io/qt-6/qsettings.html)、[QStandardPaths](https://doc.qt.io/qt-6/qstandardpaths.html)。
