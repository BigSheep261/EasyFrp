# 第 6 章：布局与界面组织

> 前置知识：会创建窗口和常用输入控件。目标：把控件组织成可缩放的界面，理解空间怎样分配，不依赖一组写死的坐标。

本章继续使用 [第二课_注册表单.py](示例代码/第二课_注册表单.py)。先把窗口拖宽、拖高，再尽量缩小，观察表单和按钮怎样移动。布局的价值就在这些变化中。

## 6.1 为什么不先写 x、y 坐标

如果把标签放在 `(10, 10)`，输入框放在 `(100, 10)`，再给它们写死宽高，初次显示可能很好看。但用户调大字体、换成高缩放屏幕、把文字翻译成更长的语言，或者缩放窗口后，原坐标就可能导致截断和重叠。

布局管理器根据父控件可用空间、每个控件的建议尺寸、最小最大尺寸、尺寸策略和伸缩比例，计算实际位置。你表达的是“这些内容竖排”“这一行右对齐”，而不是猜测每台机器上都适合的像素坐标。

窗口不是不能使用 `move()` 或 `setGeometry()`。特殊绘图、绝对坐标场景有它们的用途。常规业务表单先用布局；被布局管理的控件也不应一边让布局安排，一边反复手动调整位置。

## 6.2 四种最常用布局

| 布局 | 用途 | 典型场景 |
| --- | --- | --- |
| `QVBoxLayout` | 垂直排列 | 上方说明、中间表单、下方按钮 |
| `QHBoxLayout` | 水平排列 | 搜索框旁放按钮；一排操作按钮 |
| `QGridLayout` | 按行列排列，可跨行跨列 | 计算器、规则明确的二维控制面板 |
| `QFormLayout` | 标签与字段成对排列 | 设置页、资料编辑页 |

这些布局可以嵌套。大界面不需要一个无所不包的网格，通常先分成几块区域，每块内部选择最合适的布局。

一个 QWidget 只能安装一个顶层布局。这里的“一个”不禁止嵌套，而是说同一个窗口不要同时 `QVBoxLayout(self)` 又 `QGridLayout(self)`。正确结构是一个根布局，根布局里再放其他布局或容器控件。

## 6.3 把表单拆成一棵树

第二课的结构如下：

```text
RegistrationWindow：普通 QWidget
└── root：QVBoxLayout，窗口唯一的顶层布局
    ├── form：QFormLayout，昵称/密码/年龄/基础/目标
    ├── agree_check：QCheckBox
    ├── result_label：QLabel
    └── buttons：QHBoxLayout
        ├── 弹性空白
        ├── reset_button：QPushButton
        └── submit_button：QPushButton
```

这是**排列关系图**，不要把它与 QObject 父子树严格等同。布局负责排列，真正的控件父对象仍由所在 QWidget 等容器决定。

对应片段如下，所有控件已经创建，不能独立运行：

```python
form = QFormLayout()
form.addRow("昵称：", self.name_edit)
form.addRow("练习密码：", self.password_edit)

buttons = QHBoxLayout()
buttons.addStretch()
buttons.addWidget(self.reset_button)
buttons.addWidget(self.submit_button)

root = QVBoxLayout(self)
root.addLayout(form)
root.addWidget(self.agree_check)
root.addWidget(self.result_label)
root.addLayout(buttons)
```

`addWidget()` 放一个控件，`addLayout()` 放一个子布局，二者不能互换。`QFormLayout.addRow(label_text, field)` 接收标签文字时，会帮你创建相应标签。你也可以自己创建 `QLabel` 再放入。

不传父控件创建 `form` 和 `buttons`，是因为它们随后要成为根布局的子布局。`root = QVBoxLayout(self)` 才把根布局安装到窗口。另一种等价风格是 `root = QVBoxLayout()` 后再 `self.setLayout(root)`，选一种即可，不需要重复安装。

## 6.4 空白、间距与边距

布局周围的空白叫 contents margins，相邻项目之间的空白叫 spacing。给根布局设置一致的外边距，可以让内容不贴着边框：

```python
root.setContentsMargins(16, 16, 16, 16)  # 左、上、右、下
root.setSpacing(12)
```

这不是要求所有应用都使用 16 和 12。系统样式的默认值通常也合理；先保持一致，只有明确需求时再调整。

`addSpacing(12)` 增加一个固定长度的空白；`addStretch()` 增加能够占用剩余空间的空白。第二课把 `addStretch()` 放在两个按钮前面，所以多出来的水平空间被空白吃掉，按钮靠右。

```python
row.addStretch(1)
row.addWidget(button)
row.addStretch(1)
```

这个片段会让按钮两侧分配相同的弹性空白，从而帮助居中。伸缩因子表示相对分配权重，不是像素数。实际空间仍受控件最小、最大尺寸和尺寸策略约束。

## 6.5 stretch 与 sizePolicy 分别控制什么

设想窗口中左边是导航，右边是内容，你希望内容区域获得更多新增空间：

```python
row.addWidget(navigation_widget, 1)
row.addWidget(content_widget, 3)
```

这是 QBoxLayout 系列 `addWidget(widget, stretch=0, alignment=...)` 的常用形式。这里的 1 和 3 是伸缩因子。不要把它理解为所有情况下宽度必定精确等于 1:3，因为控件自己的尺寸限制也会参与计算。

`QSizePolicy` 表达一个控件对大小变化的意愿。常见策略可以这样初步理解：

| 策略 | 基本意图 | 常见用途 |
| --- | --- | --- |
| `Fixed` | 以建议尺寸为准，不主动随空间伸缩 | 不希望拉长的特定元素 |
| `Minimum` | 建议尺寸视为足够小的尺寸，可以变大 | 可增长但不宜变得更小的内容 |
| `Preferred` | 有偏好尺寸，也能按条件伸缩 | 很多普通控件的默认策略 |
| `Expanding` | 愿意使用更多可用空间 | 主编辑区、内容展示区 |

策略是水平和垂直两个方向分别设置的，例如片段：

```python
from PyQt6.QtWidgets import QSizePolicy

self.intro_edit.setSizePolicy(
    QSizePolicy.Policy.Expanding,
    QSizePolicy.Policy.Expanding,
)
```

如果控件同时设置了 `setMaximumHeight(100)`，即便垂直策略愿意扩展，也不能突破这个最大高度。第二课为了让初次窗口紧凑，给学习目标输入框设置了高度上限；若你希望它随窗口高度增长，就需要同时移除或调整这个上限。只改 stretch 却忽略尺寸限制，常会误以为布局失效。

`resize()` 设置窗口初始尺寸，`setFixedSize()` 则锁住尺寸。普通用户可调整窗口时，不应为了初次截图整齐就锁死整个窗口。

## 6.6 网格的行列与跨格

`QGridLayout` 使用从 0 开始的行列编号。以下是嵌入窗口的概念片段，需要先准备好相关标签、输入框与按钮：

```python
grid = QGridLayout()
grid.addWidget(name_label, 0, 0)
grid.addWidget(name_edit, 0, 1)
grid.addWidget(path_label, 1, 0)
grid.addWidget(path_edit, 1, 1)
grid.addWidget(browse_button, 1, 2)
grid.addWidget(summary_label, 2, 0, 1, 3)
grid.setColumnStretch(1, 1)
```

`summary_label` 从第 2 行第 0 列开始，占 1 行 3 列。`setColumnStretch(1, 1)` 让第 1 列具有伸缩能力，因此中间的输入区域优先获取可用空间。`setRowStretch()` 是对应的行伸缩设置。

如果只有“标签 + 输入框”两列，优先考虑 QFormLayout，通常比手动维护网格行号更清楚。不要用空 QLabel 充当几十个间隔；有 spacing、stretch 和 margins 就使用它们。

## 6.7 容器也是界面组织的一部分

`QGroupBox` 是有标题的可见分组容器，里面通常安装自己的布局。`QTabWidget` 把不同页面组织成标签页，`QStackedWidget` 一次显示一个页面，具体切换在第 8 章练习。`QSplitter` 可以让用户拖动分隔条改变各区域大小。

当内容确实会超过窗口高度时，使用 `QScrollArea`。常用结构是“滚动区域 → 内容 QWidget → 内容布局”，不是直接把一个布局传给 `setWidget()`：

```python
content = QWidget()
content_layout = QVBoxLayout(content)
content_layout.addWidget(long_form_widget)

scroll = QScrollArea()
scroll.setWidgetResizable(True)
scroll.setWidget(content)
root.addWidget(scroll)
```

这个片段要求 `root` 和 `long_form_widget` 已经存在，并导入相关类。`setWidgetResizable(True)` 允许滚动区域调整内容控件大小。滚动条是否出现，仍取决于内容的尺寸需求与当前可用空间。

一个控件同一时刻只能属于一个合适的父控件和布局位置。把同一个按钮加入两个页面，不会得到两个独立按钮；应分别创建实例，再连接到同一业务处理入口。

## 6.8 布局排错有顺序

控件不见了，先检查是否加入了已安装的布局、父容器是否可见、是否被隐藏，再考虑颜色和样式。控件无法拉伸，先看最大尺寸和固定尺寸，再看尺寸策略与 stretch。窗口缩不小，检查控件最小尺寸、文字换行和布局的最小尺寸需求。

调试时一次只改变一个因素。不要同时加 `setGeometry()`、`setFixedSize()`、多个 stretch 和样式表，然后凭感觉试到“好像可以”。先把布局树画出来，很多错误就会直接暴露。

## 6.9 本章练习与自检

1. 在第二课给根布局加统一边距和间距，再比较窗口缩放后的表现。
2. 把按钮行的 `addStretch()` 从最前移到最后，先预测再观察；再用两侧 stretch 把按钮组居中。
3. 让学习目标输入区随窗口高度增长，找出并处理阻止它增长的尺寸限制。
4. 用 QGridLayout 做一个小型“文件输出设置”面板：名称、路径、浏览按钮、跨三列说明。运行后拖宽窗口，确认输入框获得更多空间。
5. 独立画出并实现一个“左侧操作列表、右侧编辑区、底部状态提示”的布局。先列区域，再选择容器和布局，不先写坐标。

自检：你能否解释 `addWidget()` 和 `addLayout()` 的区别？能否指出窗口的唯一根布局？能否说清固定空白和弹性空白的不同？能否在字体调大时让表单仍可使用？
