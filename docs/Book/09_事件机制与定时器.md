# 第九章　事件循环怎样让界面活起来

[返回阅读地图](00_阅读地图与学习方法.md) · [上一章：对话框菜单与多页面](08_对话框菜单与多页面.md) · [下一章：对象生命期与窗口通信](10_对象生命期与窗口通信.md)

你点击按钮时，程序并不是一直执行“检查按钮有没有按下”的 Python 代码。操作系统把鼠标、键盘、窗口大小变化等消息交给 Qt，Qt 的事件循环再把事件送给相应对象。这就是图形界面与按行执行的控制台程序最明显的区别。

如果学过 MFC，可以用“消息循环、消息处理函数”的经验帮助理解。但 PyQt6 不要求你编写消息映射宏；常见做法是连接信号，必要时重写事件处理方法。

## 1. 事件与信号不是同一层概念

用户按下并松开鼠标时，按钮会先接收鼠标事件。按钮在判断这确实构成一次有效点击后，发出 `clicked` 信号。于是可以把事件理解成较底层的“发生了什么”，把信号理解成对象对外通知的“有意义的变化”。信号也可以由你的 Python 代码主动发出，并不一定来自操作系统事件。

通常优先连接信号，因为 `clicked` 已经处理了鼠标移出、键盘触发等细节。只有确实需要改变交互行为时，才重写 `mousePressEvent()`、`keyPressEvent()`、`closeEvent()` 等事件方法。仅仅为了得知一个按钮被点击，不需要自己接管鼠标事件。

`app.exec()` 启动应用事件循环。进入循环后，Qt 不断处理输入、绘制、定时器和已排队的调用。处理一个事件时，你的槽函数会占用当前线程；如果槽函数里 `time.sleep(5)` 或运行很长的计算，主线程五秒内无法及时处理其他界面工作，用户就会看到“卡住”。

## 2. 一个完整、可以独立运行的事件示例

下面代码是**完整程序**，可以保存为自己练习目录中的 `定时器练习.py`，用本书虚拟环境运行。与第四课不同，这里只使用一个普通 `QWidget` 窗口。

```python
import sys

from PyQt6.QtCore import Qt, QTimer
from PyQt6.QtGui import QCloseEvent, QKeyEvent
from PyQt6.QtWidgets import QApplication, QLabel, QMessageBox, QVBoxLayout, QWidget


class CounterWindow(QWidget):
    def __init__(self):
        super().__init__()
        self.setWindowTitle("事件和定时器")
        self.setFocusPolicy(Qt.FocusPolicy.StrongFocus)
        self.count = 0
        self.label = QLabel("定时器尚未触发；按空格暂停或恢复")
        layout = QVBoxLayout(self)
        layout.addWidget(self.label)

        self.timer = QTimer(self)
        self.timer.setInterval(500)
        self.timer.timeout.connect(self.tick)
        self.timer.start()

    def tick(self):
        self.count += 1
        self.label.setText(f"触发了 {self.count} 次；按空格暂停或恢复")

    def keyPressEvent(self, event: QKeyEvent):
        if event.key() == Qt.Key.Key_Space:
            if not event.isAutoRepeat():
                if self.timer.isActive():
                    self.timer.stop()
                else:
                    self.timer.start()
            event.accept()
            return
        super().keyPressEvent(event)

    def closeEvent(self, event: QCloseEvent):
        choice = QMessageBox.question(
            self,
            "结束练习",
            "确定关闭窗口吗？",
            QMessageBox.StandardButton.Yes | QMessageBox.StandardButton.No,
            QMessageBox.StandardButton.No,
        )
        if choice == QMessageBox.StandardButton.Yes:
            event.accept()
        else:
            event.ignore()


if __name__ == "__main__":
    app = QApplication(sys.argv)
    window = CounterWindow()
    window.show()
    sys.exit(app.exec())
```

运行后观察计数，按空格暂停、恢复；长按空格应该只切换一次；关闭窗口选择“否”应该保留窗口。这里的计数是**实际收到的 timeout 次数**，不能直接当作精确经过的秒数。

## 3. 逐段理解事件处理

`keyPressEvent()` 的名字和大小写必须准确，它不是随便命名的槽函数，而是 Qt 调用的虚方法。`event.key()` 返回键值，Qt6 使用 `Qt.Key.Key_Space` 这样的枚举路径。

键盘事件通常发给当前拥有焦点的控件。这个示例没有可编辑输入框，所以让窗口接受焦点即可。若页面里有 `QLineEdit`，键盘事件可能先到输入框；不能假定主窗口总能收到所有按键。应用级快捷操作通常更适合 `QAction` 或 `QShortcut`。

长按按键时，系统会生成重复事件。`isAutoRepeat()` 帮助我们避免把“暂停/恢复”迅速切换很多次。事件确实由当前方法处理后调用 `accept()`；不认识的键交回 `super().keyPressEvent(event)`，保留父类行为。

`closeEvent()` 接收的是关闭请求，并不等于窗口已经被销毁。调用 `event.ignore()` 可以取消关闭；`event.accept()` 表示同意。真实编辑器需要检查未保存修改，第六课文件示例给出了保存、放弃、取消三个分支。

鼠标位置同样有坐标系：`event.position()` 是相对接收控件的浮点坐标，`globalPosition()` 是屏幕坐标。不要拿一个控件的局部坐标直接与另一个控件的边界比较。

## 4. 定时器只安排机会，不创建工作线程

`QTimer(self)` 把定时器交给当前窗口管理；窗口销毁时定时器也会销毁。`setInterval(500)` 表示目标间隔 500 毫秒，`timeout` 到来后调用 `tick()`。调用 `stop()` 暂停后，`start()` 使用之前的间隔重新开始。

定时器回调仍在它所属的线程执行。在主窗口里创建的定时器，回调通常就在主线程。把耗时计算塞进 `timeout` 并不能解决卡顿。

定时器也不保证严格按时：系统忙、回调执行太久或事件循环被阻塞，都会导致延迟；错过多个间隔时，Qt 不会补发同样数量的超时信号。需要显示真实耗时，应使用 `QElapsedTimer` 或 Python 的 `time.monotonic()` 计算经过的时间，让定时器只负责定期刷新显示。

一次性的延后调用可用 `QTimer.singleShot(1000, callback)`，一秒后在事件循环有机会时执行回调。它不会让当前函数暂停一秒。若需要取消尚未执行的操作，用自己持有的 `QTimer` 并设置 `setSingleShot(True)` 更方便，因为你可以调用 `stop()`。

不要通过在循环里频繁调用 `QApplication.processEvents()` 来“修复”卡顿。这会让其他事件在当前逻辑尚未完成时进入，导致难以预料的状态重入。长任务的正确组织方式见第十五章。

## 5. 事件过滤器与绘制：先建立边界

如果要观察现有控件的事件，却不想为每个控件都建立子类，可以使用事件过滤器。观察者重写 `eventFilter(watched, event)`，再由目标调用 `installEventFilter(observer)`。返回 `True` 表示拦截并停止后续正常处理；返回 `False` 表示继续传递。它并不是“True 表示我看见了”的日志回调。

初学阶段先选子类重写，等多个控件需要同一套特殊行为时，再考虑过滤器。过滤器对象也必须有合适的生命期，不能创建后立刻失去所有引用和父对象。

`paintEvent()` 负责绘制。普通控件交给 Qt 绘制就好，自绘控件才在其中创建 `QPainter(self)`。状态变化后调用 `update()` 请求 Qt 在合适时机重绘，不要手动调用 `paintEvent()`。第十四章进一步区分样式与绘制。

## 6. API 速记与练习

| API | 输入或返回值 | 最容易误解的地方 |
| --- | --- | --- |
| `QTimer.setInterval(msec)` | 整数毫秒 | 单位不是秒 |
| `QTimer.start()` / `start(msec)` | 无业务返回值 | 启动事件通知，不启动线程 |
| `QTimer.isActive()` | `bool` | 表示定时器已启动，不表示回调正在执行 |
| `event.accept()` / `ignore()` | 无业务返回值 | 含义依赖事件类型；关闭事件中是允许或拒绝关闭 |
| `eventFilter(watched, event)` | 返回 `bool` | `True` 会吃掉事件 |
| `QWidget.update()` | 安排后续重绘 | 不保证调用时立刻绘制 |

1. 增加“重置计数”的 R 键，保留空格功能和父类默认行为。验收：按 R 后显示立即归零，而不是等下一次 timeout。
2. 把关闭确认改成只有计数大于 10 时出现。说明这是在判断关闭请求，而不是已经关闭之后补救。
3. 做一个耗时显示器：用 `QElapsedTimer` 测真实时间，每 100 毫秒刷新。验收：短暂拖动窗口后，显示时间仍与实际经过时间接近。
4. 用自己的话解释：`time.sleep()`、`QTimer.singleShot()`、后台线程分别解决什么问题？答案中应出现“阻塞当前线程”“安排稍后回调”“把工作放到另一个线程”三个不同含义。
