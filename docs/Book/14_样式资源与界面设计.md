# 第十四章　做清楚、稳定、可维护的界面

[返回阅读地图](00_阅读地图与学习方法.md) · [上一章：文件配置与数据保存](13_文件配置与数据保存.md) · [下一章：线程与后台任务](15_线程与后台任务.md)

界面设计不是最后给按钮换个颜色。用户是否看得懂、键盘能否操作、窗口缩小时会不会遮挡、出错后能不能恢复，都属于界面设计。对初学者而言，先做出清晰可靠的界面，比写一大段复杂样式更有价值。

本章介绍 Widgets 应用中常见的外观工具、图片资源、Designer 和基本自绘。它们解决不同问题：布局决定空间关系，QSS 调整已有控件外观，Designer 帮助编辑界面结构，QPainter 用于确实需要自己绘制的内容。

## 1. 从信息和操作顺序开始

一个表单先确定用户需要完成的任务，再安排输入项和按钮。必填项要有清楚标签；错误反馈放在相关位置；保存、取消、删除等动作要含义明确。需要等待的操作显示进度或忙碌状态，防止用户重复点击。

布局优先使用 `QVBoxLayout`、`QHBoxLayout`、`QFormLayout` 等。标题、正文、辅助说明之间形成稳定层级，间距保持一致。尽量避免对所有控件设置固定宽高：文本长度、系统字体、显示缩放和语言变化都会打破手工摆放的假设。

键盘可用性可以从小处开始：合理的 Tab 顺序，按钮和菜单助记键，为输入框设置标签伙伴 `label.setBuddy(edit)`，给纯图标按钮提供可理解的文字提示和无障碍名称。不要只靠红色表示错误，也提供文字说明。

## 2. QSS 是 Qt 样式表，不是浏览器 CSS

通过 `widget.setStyleSheet(text)` 可以设置局部样式，也可以用 `app.setStyleSheet(text)` 设置全局样式。样式表语法看起来像 CSS，但支持的属性、控件子元素和选择器由 Qt 定义。浏览器中的 Flexbox、Grid、动画属性不能原样搬过来；布局仍由 Qt 布局类负责。

下面是**片段**，用于已经创建好的按钮：

```python
save_button.setObjectName("saveButton")
save_button.setStyleSheet("""
QPushButton#saveButton {
    background-color: #1d4ed8;
    color: white;
    border: 1px solid #1e40af;
    border-radius: 6px;
    padding: 7px 14px;
}
QPushButton#saveButton:hover {
    background-color: #1e40af;
}
QPushButton#saveButton:focus {
    border: 2px solid #0f172a;
}
QPushButton#saveButton:disabled {
    background-color: #d1d5db;
    color: #4b5563;
    border-color: #9ca3af;
}
""")
```

`QPushButton` 是类型选择器，`#saveButton` 匹配 `objectName`，`:hover`、`:focus`、`:disabled` 匹配状态。设置 `objectName` 不会创建 Python 变量；它只是 Qt 对象上的名字。

只处理正常状态的样式可能导致按钮禁用后仍像可点击，或者键盘焦点不可见。因此修改外观时，应一起检查鼠标悬停、按下、禁用和焦点状态。Qt 样式表具有自己的级联规则；局部样式与应用级样式叠加时，不要简单照搬浏览器中对优先级的印象。

动态属性也能用于状态样式，例如 `setProperty("invalid", True)` 配合 `[invalid="true"]` 选择器。运行时改变属性后，有时需要让样式重新计算；初学阶段可先用明确的错误标签，不急于建立复杂主题系统。

## 3. 颜色、字体、图标各有工具

`QFont` 负责字体，`QPalette` 负责颜色角色，`QIcon` 负责图标，`QPixmap` 常用于显示位图。能用系统默认外观解决的问题，先保留默认行为，再对需要强调的部分做适量定制。样式表可能覆盖调色板设置，混合使用时应明确哪一种负责最终外观。

图片文件路径不要直接依赖当前工作目录。以下是**片段**，假设当前脚本旁边存在 `资源/保存.png`，并已导入 `Path`、`QIcon`：

```python
asset_path = Path(__file__).resolve().parent / "资源" / "保存.png"
icon = QIcon(str(asset_path))
if not icon.isNull():
    save_action.setIcon(icon)
```

如果图片缺失，`QIcon` 未必用 Python 异常提醒你，所以可以检查 `isNull()`。文件路径写对不代表打包时会自动包含图片；打包配置还要把资源带进去，后续打包章节会处理这个问题。

Qt6 已提供高 DPI 支持，通常无需照抄 Qt5 教程里的 `AA_EnableHighDpiScaling` 设置。使用布局、适当的最小尺寸与清晰图标，并在 100%、150%、200% 显示缩放下实际观察，比到处设置固定像素更有效。

## 4. Qt 资源系统解决路径统一问题

`.qrc` 文件声明资源与前缀，例如：

```xml
<RCC>
  <qresource prefix="/icons">
    <file alias="save.png">资源/保存.png</file>
  </qresource>
</RCC>
```

资源注册后，可通过 `QIcon(":/icons/save.png")` 使用。这里 `:/` 是 Qt 资源路径，不是磁盘根目录；路径由前缀和别名组成，与用户从哪个工作目录启动程序无关。

资源必须经过编译或注册才能使用，单独把 `.qrc` 放进文件夹并不会自动生效。**不要假设安装 `PyQt6` 就会得到 Designer、`rcc` 或 `pyrcc6`。** 网上不同 Qt 绑定和版本的教程所带工具并不完全相同。

一种可选方案是在安装了提供 `rcc` 的 Qt 开发工具后生成二进制资源：

```powershell
# 前提：rcc 已安装且可被当前终端找到；路径以实际项目为准。
rcc -binary 资源.qrc -o 资源.rcc
```

然后使用 `QResource.registerResource(资源文件的绝对路径)` 注册；它返回是否成功。另一类工具会生成 Python 资源模块，需要在程序中导入对应模块。选择这种方案前，确认生成结果使用 **PyQt6** 的导入方式；不要把为其他绑定生成的文件直接混进当前应用。

刚入门时，以 `__file__` 为基准管理少量图片已经足够。先理解路径和打包，再根据项目需要选择资源系统。

## 5. Designer 是界面编辑器，不是业务代码生成器

Qt Designer 可以拖放控件、设置属性、安排布局，保存结果为 `.ui` XML 文件。`.ui` 记录界面结构，不会自动完成保存文件、任务校验或线程管理。

对于 PyQt6，常见使用方式有两种：

| 方式 | 操作 | 优点 | 需要注意 |
| --- | --- | --- | --- |
| 生成 Python | `pyuic6` 把 `.ui` 转成 `.py` | 结构可以直接查看，运行时无需读 `.ui` | 改 `.ui` 后要重新生成 |
| 动态加载 | `PyQt6.uic.loadUi()` | 改 `.ui` 后可直接重新运行 | 发布时必须带上 `.ui`，路径和对象名要正确 |

使用本书虚拟环境时，可以先检查其中是否有 `pyuic6`，再运行类似命令：

```powershell
.\docs\Book\.venv\Scripts\pyuic6.exe .\界面.ui -o .\界面_生成.py
```

**不要在生成文件里写业务逻辑**，否则下次生成会覆盖。建立自己的窗口类，在构造时创建 `Ui_MainWindow` 并调用 `setupUi(self)`，再连接信号。实际类名取决于你的 `.ui` 文件和生成结果。

动态加载的概念写法如下，这是**片段**，要求 `.ui` 顶层类型与当前 `QMainWindow` 匹配：

```python
from pathlib import Path
from PyQt6 import uic
from PyQt6.QtWidgets import QMainWindow


class MainWindow(QMainWindow):
    def __init__(self):
        super().__init__()
        ui_path = Path(__file__).resolve().parent / "界面.ui"
        uic.loadUi(str(ui_path), self)
        # .ui 中按钮的 objectName 必须是 saveButton。
        self.saveButton.clicked.connect(self.save_document)

    def save_document(self):
        print("在这里连接自己的保存逻辑")
```

Designer 的安装方式随平台和发行渠道而变，某些第三方工具包还与特定 Python、PyQt6 版本绑定。先确认兼容性，不要为获得一个拖拽编辑器随意破坏已能运行的虚拟环境。没有 Designer 也完全可以用本书的手写布局独立开发。

## 6. 自绘控件：状态变化后请求重绘

进度仪表、波形、流程节点等内容可能无法通过已有控件和 QSS 表达，此时才考虑 `QPainter`。在 `paintEvent()` 中创建画笔对象，根据当前状态绘制；状态改变时调用 `update()`，由 Qt 安排重绘。

以下是**类定义片段**，需要已有 `QWidget`、`QPainter`、`QColor`、`Qt` 导入及应用入口：

```python
class StatusLamp(QWidget):
    def __init__(self, parent=None):
        super().__init__(parent)
        self.online = False
        self.setMinimumSize(36, 36)

    def set_online(self, online: bool):
        self.online = online
        self.update()

    def paintEvent(self, event):
        painter = QPainter(self)
        painter.setRenderHint(QPainter.RenderHint.Antialiasing)
        painter.setPen(Qt.PenStyle.NoPen)
        painter.setBrush(QColor("#15803d" if self.online else "#6b7280"))
        size = min(self.width(), self.height()) - 12
        x = (self.width() - size) // 2
        y = (self.height() - size) // 2
        painter.drawEllipse(x, y, size, size)
```

不要在绘制方法里读文件、发网络请求或改变导致反复重绘的状态。自绘圆灯也应配合文字“在线/离线”，让信息不只依赖颜色。若以后需要管理大量可交互图形对象，可继续研究 `QGraphicsScene` 和 `QGraphicsView`；它们与表格数据的模型视图是不同的问题领域。

## 7. 练习与自检

1. 为第四课统一设置间距和按钮样式，保留清晰的键盘焦点。验收：不用鼠标可以切换输入项并提交对话框。
2. 给保存动作加入图标，然后从另一个工作目录启动程序。验收：仍能找到图片；移走图片时你能解释和定位问题。
3. 在 Designer 中复刻一个简单表单，分别尝试生成 Python 和动态加载。写下哪一个文件属于设计源文件、哪一个会被生成覆盖。
4. 将自绘状态灯与一个复选框连接，并加入状态文字。验收：缩放窗口后圆灯仍居中，没有通过手动调用 `paintEvent()` 强迫刷新。
5. 做一次界面走查：窄窗口、长中文文本、禁用按钮、键盘操作和高缩放。列出实际发现的问题，再修复最影响使用的一项。
