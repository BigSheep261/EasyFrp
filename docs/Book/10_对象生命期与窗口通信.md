# 第十章　谁拥有对象，谁通知谁

[返回阅读地图](00_阅读地图与学习方法.md) · [上一章：事件机制与定时器](09_事件机制与定时器.md) · [下一章：列表表格与树](11_列表表格与树.md)

当窗口从一个变成几个，初学者经常遇到两种看似矛盾的问题：有的窗口一出现就消失，有的窗口已经关闭却仍占着内存。还有一种报错是 `wrapped C/C++ object ... has been deleted`：明明 Python 变量还在，为什么对象却不存在了？

理解这些问题，需要同时考虑 **Python 的引用**和 **Qt 的对象所有权**。它们有关联，但不是同一套规则。本章也讨论窗口之间怎样传递信息，避免所有对象彼此访问、越写越乱。

## 1. parent 是所有权，不只是摆放位置

多数 Qt 对象继承 `QObject`。构造时给出父对象，会建立一棵对象树。父对象销毁时，它拥有的子对象会一起销毁。例如 `QTimer(window)` 通常不需要你在窗口结束时手工逐个删除。

对于 `QWidget`，父子关系还经常影响显示位置：普通子控件显示在父控件内部。不过“拥有者”和“显示形式”不能完全混为一谈。`QDialog(parent)` 即使有父对象，也仍然是一个对话框窗口；非可视对象 `QTimer` 则根本没有摆放位置。

当你把控件加入已安装在某个窗口上的布局时，Qt 通常会让布局中的控件归属于那个容器窗口。布局负责安排位置，但不要把布局本身想成所有控件的可视父控件。`setCentralWidget()` 则明确把中心控件交给主窗口拥有。

不是每个 Qt 类型都是 `QObject`。`QTableWidgetItem`、`QListWidgetItem` 等项目对象有各自的所有权约定；不要看到 Qt 类型就盲目套用 `parent`、`deleteLater()`。

## 2. Python 变量活着，不代表底层对象一定活着

PyQt 的 Python 对象包装着底层 Qt 对象。一个没有 Qt 父对象、也没有持久 Python 引用的临时顶层窗口，可能很快被回收：

```python
# 错误示意片段：dialog 只在方法里被临时引用。
def show_details(self):
    dialog = QDialog()
    dialog.show()
```

`show()` 立即返回；方法结束后，这个局部变量不会自动变成主窗口的成员。可靠做法是明确所有权，并把还要访问的对象保存在 `self.details_dialog` 等属性中。

反过来，保存 Python 引用并不能阻止 Qt 父对象删除子对象。如果父窗口已销毁，再对旧的 Python 包装对象调用方法，就可能出现“底层对象已删除”。因此“我还有这个变量”不是安全访问对象的充分条件。

在实践中采用简单约定就好：长期使用的对象保存为属性；子对象设置合适的父对象；销毁后不要复用旧包装对象；临时对话框用完明确安排释放。不要依靠记住 Python 引用计数的所有细节来设计界面。

## 3. hide、close 和 deleteLater 的区别

`hide()` 只隐藏控件。`close()` 先发送关闭事件，事件被接受后通常隐藏窗口；它**不保证销毁对象**。如果设置 `Qt.WidgetAttribute.WA_DeleteOnClose`，窗口接受关闭时才会走销毁流程。

`deleteLater()` 请求 Qt 在适当的事件循环时机删除对象，调用结束后并不表示对象已经销毁。它适合处理信号回调过程中不便立即删除对象的情况。应在事件循环仍有机会处理该请求时使用；不要把它理解成程序退出后无论如何都会运行的清理函数。

Qt 会自动断开被销毁对象参与的相应信号连接，但这不等于你的列表、字典、属性会自动清除所有旧引用。重要状态仍要由自己维护。

第四课的模态对话框使用 `exec()`，读取结果后调用 `deleteLater()`。对非模态窗口，常见策略有两个：关闭后保留对象，下次再次显示；或者关闭时销毁，下次重新创建。选好一种，并让代码符合它，避免两套策略混在一起。

## 4. 一个完整的非模态通信示例

下面是**完整程序**，可以另存为练习文件运行。子窗口只发出“名称已提交”的信号，主窗口决定怎样响应。主窗口保存子窗口引用，子窗口关闭后销毁，再次打开时重新创建。

```python
import sys

from PyQt6.QtCore import Qt, pyqtSignal
from PyQt6.QtWidgets import (
    QApplication, QDialog, QLabel, QLineEdit,
    QPushButton, QVBoxLayout, QWidget,
)


class NameWindow(QDialog):
    name_submitted = pyqtSignal(str)  # 信号声明在类上。

    def __init__(self, parent=None):
        super().__init__(parent)
        self.setWindowTitle("输入名称")
        self.setAttribute(Qt.WidgetAttribute.WA_DeleteOnClose)
        self.edit = QLineEdit()
        button = QPushButton("应用名称")
        button.clicked.connect(self.submit)
        layout = QVBoxLayout(self)
        layout.addWidget(self.edit)
        layout.addWidget(button)

    def submit(self):
        name = self.edit.text().strip()
        if name:
            self.name_submitted.emit(name)


class MainWindow(QWidget):
    def __init__(self):
        super().__init__()
        self.setWindowTitle("窗口通信")
        self.name_window = None
        self.label = QLabel("尚未设置名称")
        button = QPushButton("打开名称窗口")
        button.clicked.connect(self.open_name_window)
        layout = QVBoxLayout(self)
        layout.addWidget(self.label)
        layout.addWidget(button)

    def open_name_window(self):
        if self.name_window is None:
            self.name_window = NameWindow(self)
            self.name_window.name_submitted.connect(self.label.setText)
            self.name_window.destroyed.connect(self.clear_name_window)
        self.name_window.show()
        self.name_window.raise_()
        self.name_window.activateWindow()

    def clear_name_window(self):
        self.name_window = None


if __name__ == "__main__":
    app = QApplication(sys.argv)
    window = MainWindow()
    window.show()
    sys.exit(app.exec())
```

测试三个流程：连续点击打开只出现一个子窗口；提交名称时主窗口立即更新；关闭子窗口后可以再次正常打开。`raise_()` 和 `activateWindow()` 请求把窗口置前并激活，最终效果仍受操作系统窗口管理规则影响。

## 5. 让窗口知道“发生了什么”，而不是“对方内部长什么样”

示例中，子窗口没有写 `self.parent().label.setText(...)`。它只发出 `name_submitted(str)`，不知道接收者是一个标签、一个数据模型，还是一个记录日志的方法。这让子窗口可以在另一处复用。

主窗口在创建对象时连接信号，相当于负责接线。多个同级页面通信时，也优先让共同的上层对象连接它们，或者让它们共享一个职责清晰的数据模型。不要让 A 页面导入 B 页面，B 页面又导入 A 页面，再用全局变量互相寻找实例。

将上面的两个类拆文件时，主窗口模块导入子窗口模块即可；子窗口模块只导入 PyQt6 和真正共用的数据类型。子窗口无需为了发送信号再反向导入主窗口类，循环导入自然就减少了。

信号参数也应该表达业务事实，例如任务编号、新名称、执行结果。不要动不动把整个主窗口实例传来传去。对于可变列表、字典，不要假定发信号就会自动深拷贝；尤其跨线程时，应明确哪些数据可以修改，第十五章会继续展开。

## 6. API、排错和练习

| API / 概念 | 意义 | 使用提醒 |
| --- | --- | --- |
| `QObject(parent)` | 建立对象所有权 | 父对象销毁会删除子对象 |
| `QObject.parent()` | 返回父对象或 `None` | 所有者不等于业务服务入口 |
| `destroyed` 信号 | 通知对象正在销毁 | 清理引用，不再访问已销毁对象内部 |
| `deleteLater()` | 请求延后销毁 | 不是立即删除，也不是隐藏 |
| `WA_DeleteOnClose` | 接受关闭后销毁窗口 | 配合重建逻辑和清理引用 |
| `pyqtSignal(str)` | 声明携带字符串的信号 | 放在继承 `QObject` 的类体中 |

排错时先检查三件事：对象是否只有临时局部引用；父对象是否已经被删除；窗口关闭策略是否与再次打开策略一致。如果同一个槽执行了多次，再检查是否每次显示页面都重复 `connect()`。一般在创建对象时连接一次，而不是每次刷新都连接。

1. 把非模态示例改成“关闭后保留、再次打开保留输入文字”。提示：移除关闭销毁属性后，生命周期策略发生了改变。
2. 增加第二个标签，同一个 `name_submitted` 同时更新两个显示。验收：子窗口代码无需认识这两个标签。
3. 将示例拆为主窗口模块、子窗口模块、入口模块。画出导入箭头，确认没有双向导入。
4. 口头解释：“为什么局部变量的对话框可能消失？为什么保存在 `self` 中的对象仍可能报已删除？”两问分别涉及 Python 引用和 Qt 所有权，不能用同一句话含糊带过。
