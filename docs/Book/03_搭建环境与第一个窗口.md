# 第 3 章：搭建环境与第一个窗口

> 前置知识：第 1、2 章。目标：在独立环境中运行窗口，能逐段解释应用启动代码，遇到导入错误时知道先检查什么。

本章只说明供你自己执行的安装步骤；教材编写不会替你修改全局 Python 或当前项目环境。以下命令按 **Windows PowerShell、从项目根目录 `C:\PersonCode\EasyFrp` 启动** 编写。其他系统的虚拟环境解释器通常位于 `.venv/bin/python`，对应替换即可。

## 3.1 先知道“安装到哪个 Python”

一台电脑可能有系统 Python、项目虚拟环境、IDE 自动创建的环境。`pip` 安装成功但 `import PyQt6` 失败，常常是安装包的 Python 和运行程序的 Python 不是同一个。

虚拟环境可以给这套学习示例准备独立的包集合。它不复制整个操作系统，也不是一个虚拟机；重点是把解释器入口、安装包与项目关联起来。

先在 PowerShell 中确认 Python：

```powershell
Set-Location 'C:\PersonCode\EasyFrp'
py -0p
py -3.12 --version
```

`py` 是 Windows 常见的 Python 启动器，`-0p` 列出它发现的版本与路径。如果没有 `py` 命令，用你已经安装的 Python 的完整路径执行 `--version`。本书面向 Python 3.12 或更高版本；以下用 3.12 演示，有 3.13 时可以相应替换，并确认所用 PyQt6 版本提供匹配的安装包。

## 3.2 创建独立的学习环境

从项目根目录执行：

```powershell
py -3.12 -m venv .\docs\Book\.venv
.\docs\Book\.venv\Scripts\python.exe -m pip install --upgrade pip
.\docs\Book\.venv\Scripts\python.exe -m pip install "PyQt6>=6,<7"
```

`-m venv` 运行 Python 自带的虚拟环境模块。`python.exe -m pip` 则明确表示“给这个解释器安装包”，比直接敲一个来源不明的 `pip` 更容易排查。第二、三行需要网络和可用的 Python 包源。

这里特意用完整的相对解释器路径，因此无需激活环境，也不会遇到 PowerShell 拒绝执行 `Activate.ps1` 的问题。你当然可以学会激活，但“激活”主要是临时调整命令搜索路径，并不是虚拟环境可用的前提。

`.venv` 内包含本机依赖，不应作为教材源代码提交到版本库；如果使用 Git，确认相应忽略规则即可。不要为了学习重装已有项目环境，也不要无意把当前项目依赖清单覆盖掉。

检查安装和运行路径：

```powershell
.\docs\Book\.venv\Scripts\python.exe -c "import sys; from PyQt6.QtCore import PYQT_VERSION_STR, QT_VERSION_STR, qVersion; print(sys.executable); print('PyQt:', PYQT_VERSION_STR); print('Qt binding build:', QT_VERSION_STR); print('Qt runtime:', qVersion())"
```

这里会显示解释器路径、PyQt 版本、绑定构建时的 Qt 版本与实际加载的 Qt 运行库版本。后两者通常接近，但概念不同。排查版本相关问题时，保留这些信息比只说“我装了最新版”有用。

## 3.3 让 IDE 使用同一个解释器

如果在终端能运行，在 IDE 中却提示找不到 PyQt6，先不要重复安装。打开 IDE 的 Python 解释器配置，选择：

```text
C:\PersonCode\EasyFrp\docs\Book\.venv\Scripts\python.exe
```

VS Code 可使用“Python: Select Interpreter”；PyCharm 可在项目 Python Interpreter 设置中添加已有解释器。不同版本菜单可能略有变化，判断标准是解释器路径一致。IDE 的终端、代码运行按钮、测试配置可能分别使用不同环境，需要分别确认。

Qt Designer 是可选的界面设计工具；写第一个窗口不需要它。不要因为网络上有人推荐，就先安装一大组 `pyqt6-tools` 等额外包；它们可能有自己的版本约束。第 14 章再解释 Designer 和 `.ui` 文件。

## 3.4 运行你的第一个窗口

完整代码已经放在 [第一课_你好窗口.py](示例代码/第一课_你好窗口.py)。从项目根目录运行：

```powershell
.\docs\Book\.venv\Scripts\python.exe .\docs\Book\示例代码\第一课_你好窗口.py
```

预期出现标题为“第一课：你好，PyQt6”的窗口，里面有一行文字和一个按钮。点击按钮后，文字显示点击次数；拖动边框时，布局随窗口调整；关闭最后一个窗口后，程序正常返回终端。

下面按职责解释程序。下面各段是从完整文件摘出的**局部片段，不要分别当成完整程序执行**。

### 第一步：导入需要的工具

```python
import sys
from PyQt6.QtWidgets import QApplication, QLabel, QPushButton, QVBoxLayout, QWidget
```

`QApplication` 管理 GUI 应用。`QWidget` 提供基础窗口能力。`QLabel` 显示文字，`QPushButton` 提供按钮，`QVBoxLayout` 把内容按竖直方向排列。只导入当前需要的类，比通配符导入 `*` 更容易看清代码依赖。

### 第二步：定义窗口

```python
class GreetingWindow(QWidget):
    def __init__(self) -> None:
        super().__init__()
        self.click_count = 0
        self.setWindowTitle("第一课：你好，PyQt6")
        self.resize(420, 200)
```

窗口是一个对象，所以把它的状态和操作放在一个类里。`click_count` 是普通 Python 数据；`setWindowTitle(str)` 设置标题；`resize(width, height)` 设置初始尺寸，不是锁死尺寸。Qt 使用逻辑尺寸，操作系统的缩放比例可能影响实际物理像素，不必将 `420` 理解为所有屏幕上完全相同的物理像素宽度。

### 第三步：创建控件并安排位置

```python
self.message_label = QLabel("欢迎！试着点击下面的按钮。")
self.greet_button = QPushButton("打个招呼")
layout = QVBoxLayout(self)
layout.addWidget(self.message_label)
layout.addWidget(self.greet_button)
```

两个控件先被创建，再加入窗口的布局。`QVBoxLayout(self)` 把布局安装到当前窗口。加入该布局的控件会成为窗口中的子控件，由布局管理几何位置，也由 Qt 的父子关系参与生命周期管理。

`self.message_label` 保存引用，因为点击处理方法稍后要修改它。布局暂时只在初始化时使用，所以用局部变量 `layout` 即可。不要把 `layout` 误认为屏幕上另一个能看见的控件；它负责安排位置。

### 第四步：登记交互规则

```python
self.greet_button.clicked.connect(self.say_hello)
```

意思是“按钮被点击后，请调用本窗口的 `say_hello` 方法”。没有调用括号，因为现在只登记，将来才执行。接收方法如下：

```python
def say_hello(self) -> None:
    self.click_count += 1
    self.message_label.setText(f"你好！你已经点击了 {self.click_count} 次。")
```

先修改数据，再根据数据更新文字。`QPushButton.clicked` 实际可以提供一个 `checked: bool` 参数；这里的接收方法不需要它，PyQt 可以把额外的信号参数丢弃。第 7 章会完整解释参数匹配。

### 第五步：创建应用，显示窗口，进入循环

```python
def main() -> int:
    app = QApplication(sys.argv)
    window = GreetingWindow()
    window.show()
    return app.exec()


if __name__ == "__main__":
    sys.exit(main())
```

必须先创建 `QApplication`，再创建 GUI 控件。一个普通 GUI 进程只创建一个应用对象，多个窗口共享它。`sys.argv` 是命令行参数列表，Qt 会读取其中与自身相关的参数。

`window.show()` 让窗口进入显示状态。`app.exec()` 启动事件循环，通常直到应用退出才返回一个整数退出码。`sys.exit(...)` 把退出码交回系统。

`window` 是 `main()` 的局部变量，但 `app.exec()` 运行期间 `main()` 尚未结束，因此窗口引用还在。以后如果在一个马上返回的函数里创建独立窗口，就需要注意保存引用，第 10 章会讨论。

## 3.5 第一次遇到错误时怎么查

| 现象 | 优先检查 | 原因说明 |
| --- | --- | --- |
| `No module named PyQt6` | 运行程序的 `sys.executable` | 通常是解释器不一致或包没装成功 |
| `Must construct a QApplication before a QWidget` | 应用创建顺序 | 在应用对象之前创建了控件，可能发生在模块顶层 |
| 找不到 `.py` 文件 | 当前目录和文件路径 | 本章命令要求从项目根目录运行 |
| 窗口没有出现或一闪而过 | 完整 traceback、`show()`、`exec()` | 可能有异常，或缺少显示/事件循环步骤 |
| 点击时出现 `NoneType` 相关错误 | `connect` 是否写了多余括号 | 很可能把方法返回值当回调传入 |
| Qt 平台插件无法初始化 | 完整错误、环境混用、系统依赖 | 不要随机下载 DLL 或盲改插件路径 |

保留终端窗口很重要，异常通常在那里。排查时先用本书第一个最小示例复现：最小示例正常，说明问题更可能在自己的代码；最小示例也失败，再检查安装与系统环境。Linux 还需要图形显示环境及相应系统库，纯服务器终端不能默认显示桌面窗口。

## 3.6 本章练习与自检

1. 修改窗口标题、初始尺寸、按钮文字。先预测对应语句，再修改运行。
2. 让每次点击增加 2，保持显示文字来自 `click_count`，不要只替换字符串里的数字。
3. 新增一个“归零”按钮，连接到一个有名字的方法，并让数据和显示同时归零。
4. 在 `main()` 的 `app.exec()` 前后各加一条 `print`，观察第二条何时执行。完成后恢复示例或保留个人练习副本。
5. 关闭参考代码，重新写出“导入 → 定义窗口 → 创建应用 → 显示 → 事件循环”的骨架。控件方法可以查文档，但要自己说明顺序。

自检：你能说出当前使用哪个解释器，能解释为什么 `app.exec()` 后面的代码不会立刻运行，能在不复制整段代码的情况下增加一个按钮。达到这些标准再进入控件章节。
