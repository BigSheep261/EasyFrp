# 第八章　让一个窗口承担完整的操作流程

[返回阅读地图](00_阅读地图与学习方法.md) · [上一章：信号与槽](07_信号与槽.md) · [下一章：事件机制与定时器](09_事件机制与定时器.md)

学完控件、布局和信号之后，你已经能做出“点按钮，改文字”的窗口。本章把这些能力组织成一个真正可使用的小应用：菜单提供命令，对话框收集信息，多个页面共享同一个主窗口。先不追求外观；我们要让每一步操作的责任清楚。

本章完成后，你应该能回答：为什么点击“取消”不能更新主界面？为什么菜单和工具栏可以执行同一个命令？切换页面时，旧页面的数据为什么还在？

## 1. 三种窗口，先分清用途

`QWidget` 是普通可视部件，适合组成页面，也可以作为简单顶层窗口。`QMainWindow` 为完整应用提供菜单栏、工具栏、状态栏以及中心区域。`QDialog` 专门用于完成一次有明确结果的交互，例如修改名称、输入参数、选择导出选项。

可以把主窗口想成办公室，对话框是临时递给你的表格，页面是办公室里的不同工作区域。不要每切换一个功能就新建一个主窗口；这通常会带来窗口过多、状态不同步的问题。

使用 `QMainWindow` 时，把页面容器传给 `setCentralWidget()`。不要直接给主窗口安装普通布局，因为它自身已有管理这些区域的内部布局。如果熟悉 MFC，可以把菜单命令与 `QAction` 联系起来，但 PyQt6 的具体组织方式依然以对象和信号为准。

这个示例使用两个类。`NameDialog` 收集并校验名称，`MainWindow` 决定名称怎样影响主界面。这种责任划分比“让对话框到处寻找主窗口控件并修改它们”更容易维护。

## 3. 对话框的结果比它长什么样更重要

下面是完整文件中的片段，不能单独运行：

```python
dialog = NameDialog(self.display_name, self)
try:
    if dialog.exec() == QDialog.DialogCode.Accepted:
        self.display_name = dialog.selected_name()
        self.refresh_welcome()
finally:
    dialog.deleteLater()
```

`exec()` 显示模态对话框，并在对话框结束后返回结果代码。模态表示用户暂时不能操作它所阻塞的其他窗口；界面事件仍在处理，并不是 Python 执行了一个不断等待的死循环。`accept()` 结束对话框并给出 `Accepted`，`reject()` 给出 `Rejected`。按取消、按 Esc 或关闭对话框通常属于拒绝。

“点击确定”与“内容有效”是两个不同判断。示例让按钮先调用 `check_and_accept()`：检查 `.text().strip()` 非空后才调用 `accept()`。如果校验失败，只展示错误并继续留在对话框里。调用者也只有收到 `Accepted` 才读取结果。

`QDialogButtonBox` 提供适合系统习惯的按钮排列；它发出 `accepted`、`rejected` 信号，但不会替你决定业务规则。你仍要把信号连接到合适的方法。

示例每次创建一个临时对话框，因此读取数据后使用 `deleteLater()` 释放它。不要在删除后再读取其中的输入框。第十章会详细说明对象生命期。

简单输入也可以用 `QInputDialog`。例如 `getText()` 返回 `(text, accepted)`；取消时不能只检查字符串，要检查 `accepted`。`QFileDialog` 用于选路径，第十三章专门讨论它；`QMessageBox` 用于提醒、错误和有限选项的确认。

进阶时，你还会遇到 `dialog.open()`：它立即返回，随后通过 `finished(int)`、`accepted()` 等信号接收结果。这有利于避免嵌套事件循环；本章先掌握短小、同步的 `exec()` 使用方式，不要在模态对话框里运行长时间任务。

## 4. QAction 是“操作”，菜单只是操作的入口

下面的片段同样依赖示例中的 `self`：

```python
rename_action = QAction("修改名称…", self)
rename_action.setShortcut("Ctrl+R")
rename_action.triggered.connect(self.rename_user)
menu.addAction(rename_action)
toolbar.addAction(rename_action)
```

这里创建的不是两个“修改名称”功能，而是一个动作、两个入口。动作拥有标题、快捷键、是否可用、是否选中等状态。对它调用 `setEnabled(False)`，菜单和工具栏中的入口会同时不可用。以后做“没有文档时禁用保存”，应该修改动作状态，而不是分别管理每个按钮。

PyQt6 中 `QAction` 位于 **`PyQt6.QtGui`**；旧文章可能从 `QtWidgets` 导入，照搬会出错。优先使用 `QKeySequence.StandardKey.Save` 等标准快捷键，系统能够按平台习惯选择组合键。示例的 `Ctrl+R` 是自定义组合键。

`triggered` 可以携带 `checked: bool` 参数，用于可勾选动作；本例连接的不接收参数的方法也能工作。自己写 lambda 转发数据时，要记得这个信号参数可能占据 lambda 的第一个位置。

## 5. 页面切换是改变“当前显示谁”

`QStackedWidget` 把多个页面放进一个容器，一次显示其中一个。`addWidget(page)` 返回页面索引；第一个为 0，第二个为 1。第四课让导航列表与页面按相同顺序添加，因此可以直接连接：

```python
self.navigation.currentRowChanged.connect(self.pages.setCurrentIndex)
```

这是示例片段，依赖已经建立好的导航和页面。当前行号传给 `setCurrentIndex()` 后，容器切换页面。已经创建的旧页面依然存在，所以笔记文本保留着。若使用 `QTabWidget`，标签页和切换入口已经整合在一起，适合较少且同级的页面。

实际项目增加、移除或重排导航时，不要再假定“导航行号永远等于页面索引”。可以通过页面对象调用 `setCurrentWidget(page)`，或者维护明确的功能标识到页面对象的映射。

## 6. 这一章常用 API

| API | 关键参数与返回值 | 适用场景 |
| --- | --- | --- |
| `QDialog.exec()` | 无必填参数；返回对话框结果代码 | 短小的模态输入流程 |
| `accept()` / `reject()` | 无返回数据；改变结果并结束对话框 | 提交或取消 |
| `QInputDialog.getText(...)` | 标题、提示文字等；返回文本和确认标志 | 一项文字输入 |
| `QAction(text, parent)` | 文案、所属对象；得到动作对象 | 多入口共享一项操作 |
| `QStackedWidget.addWidget(widget)` | 页面控件；返回整数索引 | 注册页面 |
| `setCurrentIndex(index)` | 整数索引；没有业务返回值 | 切换当前页 |
| `statusBar().showMessage(text, timeout)` | `timeout` 是毫秒；0 表示持续显示 | 简短、不阻塞的反馈 |

这些返回值值得特别区分：`addWidget()` 的整数是页面位置；`exec()` 的结果表达确认还是取消。它们都是整数相关值，但含义完全不同。

## 7. 常见错误与练习

常见错误包括：对话框一关闭就保存输入，忽略取消；每次切页都创建新控件导致旧数据丢失；把所有功能写进主窗口一个巨大方法；给 `QMainWindow` 直接调用 `setLayout()`；把 `QAction` 从旧版本的模块位置导入。

完成下面四项练习，再向下一章前进：

1. 增加“学习目标”第三页。验收：反复切换页面后，各页面内容保持；状态栏显示正确名称。
2. 把名称限制为 1—20 个非空白字符。验收：无效输入时对话框保持打开，取消时旧名称不变。
3. 增加一个“只读笔记”可勾选动作，让菜单和工具栏共享它。提示：`setCheckable(True)`、`toggled(bool)`、`QTextEdit.setReadOnly()`。
4. 用自己的话画出一次改名的数据流：主窗口当前值 → 对话框输入 → 校验 → 结果代码 → 主窗口更新。能解释取消分支为什么不改值，才算理解。
