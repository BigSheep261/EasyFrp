# 第 21 章：扩展模块与技术选择——知道工具箱里还有什么

[上一章：打包发布与维护](20_打包发布与维护.md) · [阅读地图](00_阅读地图与学习方法.md) · [下一章：综合实战_桌面任务管理器](22_综合实战_桌面任务管理器.md)

本章目标：建立 PyQt6 模块地图，遇到新需求时知道从哪里查起，并学会判断是否真的需要某项技术。没有必要把 Qt 的所有类和函数背下来；能够根据需求找到正确文档、验证最小示例，才是可以长期使用的能力。

## 1. 模块、类、方法是什么关系

`PyQt6` 是 Python 包；`QtWidgets` 是其中一个模块；`QPushButton` 是模块提供的类；`setText()` 是按钮继承得到或自身提供的方法；`clicked` 是信号。

因此 `from PyQt6.QtWidgets import QPushButton` 的含义是从模块导入一个类，不是给程序“开启一个按钮功能”。每个类还带有构造函数、属性、信号、普通方法和可重写事件处理函数，查文档时应区分它们。

本书重点使用 Qt Widgets 路线，因为它适合表单、表格、设置页和常见桌面工具。下面的模块地图帮助你扩展，不要求按顺序把所有模块重新学一遍。

## 2. 核心模块地图

| 模块 | 主要能力 | 典型类或入口 | 适用场景 |
| --- | --- | --- | --- |

| `QtTest` | 测试输入与信号观察 | `QTest`、`QSignalSpy` | 自动验证界面行为 |
| `QtPrintSupport` | 打印、打印设置、预览 | `QPrinter`、`QPrintDialog`、`QPrintPreviewDialog` | 票据、报表、打印文档 |

| `QtSvg` / `QtSvgWidgets` | SVG 渲染及控件 | `QSvgRenderer`、`QSvgWidget` | 可缩放图形与图标 |
| `QtOpenGL` / `QtOpenGLWidgets` | OpenGL 资源与绘图控件 | `QOpenGLBuffer`、`QOpenGLWidget` | 自定义 GPU 绘图 |

这些名称是一张导航图，实际可导入模块和可用后端受 PyQt 发行版本、平台、wheel 构建及系统依赖影响。不要仅凭看到一张 C++ Qt 模块表，就认定当前 Python 环境一定拥有相同绑定。

## 3. 哪些功能要单独安装或特别核对

Qt WebEngine 的 PyQt 绑定使用单独分发的 `PyQt6-WebEngine` 包，常用模块是 `QtWebEngineCore`、`QtWebEngineWidgets` 和 `QtWebEngineQuick`。其中 `QWebEngineView` 能嵌入网页浏览能力，也会带来更多体积、进程、资源和更新维护需求。

某些 Qt 扩展模块还由独立的 Riverbank 包提供，例如对应 Qt Charts 的 `PyQt6-Charts`、对应数据可视化的 `PyQt6-DataVisualization`。其支持状态、Qt 版本范围和许可需要按你选定的版本核对，不要照旧博客盲目安装。

“Qt C++ 提供了某模块”“PyQt6 提供该模块的 Python 绑定”“当前机器装好了对应绑定和运行库”是三个不同事实。遇到 `ModuleNotFoundError` 时，先确认包名和绑定是否存在，再讨论代码写法。

官方入口：[PyQt6 文档](https://www.riverbankcomputing.com/static/Docs/PyQt6/)、[Qt 6 模块列表](https://doc.qt.io/qt-6/qtmodules.html)、[Qt 6 类参考](https://doc.qt.io/qt-6/classes.html)。Qt 文档多使用 C++ 示例，理解概念以后还需要转换为 PyQt6 的 Python API。

## 4. JSON、SQLite 和 QtSql 如何选择

只有少量设置、任务数量不大且通常整份读写时，JSON 简单直观。数据需要查询、排序、关联、约束和可靠批量更新时，SQLite 更合适。SQLite 是嵌入式数据库，常见使用方式是一个数据库文件，不需要另起数据库服务器。

Python 标准库的 `sqlite3` 很适合让业务层保持纯 Python；`QtSql` 则方便和 `QSqlTableModel` 等 Qt 数据模型结合。两条路线都合理，按架构和界面需求选择，不需要因为用了 Qt 就强行把全部数据库代码换成 QtSql。

以下是可单独保存运行的最小 SQLite 演示，创建临时数据库并在退出时自动清理：

```python
import sys
from pathlib import Path
from tempfile import TemporaryDirectory
from PyQt6.QtCore import QCoreApplication
from PyQt6.QtSql import QSqlDatabase, QSqlQuery

def demonstrate(database_path):
    connection_name = "lesson_tasks"
    db = QSqlDatabase.addDatabase("QSQLITE", connection_name)
    db.setDatabaseName(str(database_path))
    query = None
    try:
        if not db.open():
            raise RuntimeError(db.lastError().text())
        query = QSqlQuery(db)
        if not query.exec("CREATE TABLE tasks (id INTEGER PRIMARY KEY, title TEXT NOT NULL)"):
            raise RuntimeError(query.lastError().text())
        if not db.transaction():
            raise RuntimeError(db.lastError().text())
        try:
            if not query.prepare("INSERT INTO tasks(title) VALUES (:title)"):
                raise RuntimeError(query.lastError().text())
            query.bindValue(":title", "学习 SQLite 的事务")
            if not query.exec():
                raise RuntimeError(query.lastError().text())
            if not db.commit():
                raise RuntimeError(db.lastError().text())
        except Exception:
            db.rollback()
            raise
        if not query.exec("SELECT id, title FROM tasks ORDER BY id"):
            raise RuntimeError(query.lastError().text())
        while query.next():
            print(query.value(0), query.value(1))
    finally:
        # 先释放查询及连接句柄，再从 Qt 的连接注册表移除连接。
        query = None
        db.close()
        db = QSqlDatabase()
        QSqlDatabase.removeDatabase(connection_name)

def main():
    app = QCoreApplication(sys.argv)
    with TemporaryDirectory() as folder:
        demonstrate(Path(folder) / "任务.sqlite")

if __name__ == "__main__":
    main()
```

`QCoreApplication` 提供 Qt 核心环境；这里没有 GUI，也没有异步任务，因此不需要调用事件循环等待。不要把这种省略 `exec()` 的写法套到窗口程序上。

## 5. 参数绑定与事务为什么重要

`prepare()` 准备 SQL 结构，`:title` 是占位符，`bindValue()` 将实际值作为数据交给数据库。不要使用 f-string 把用户输入拼进 SQL。标题里包含单引号时，参数绑定能正确处理，也能防止输入被当作 SQL 语句执行。

参数绑定用于值，不能直接替代任意表名、列名或 `ORDER BY` 方向。需要动态选择列时，应从自己定义的允许列表中选择列名。

事务表示一组更新要么全部提交，要么在失败时回滚。例如扣减一个账户余额并增加另一个账户余额，不能只做成其中一半。QtSql 中 `transaction()` 开始事务、`commit()` 提交、`rollback()` 回滚，返回 `bool` 表示调用是否成功，必须检查失败。

SQLite 可以同时有多个读取者，但写入并发仍有限制。耗时查询会占用当前线程；换到后台线程时，应在对应线程内创建、使用和关闭连接，不要把 GUI 线程的数据库连接随意传过去共用。

## 6. 其他模块的学习门槛

串口通信需要理解波特率、数据位、校验位、停止位以及设备协议。`readyRead` 仍只代表收到一些字节；一条消息可能分多次到达，需要按协议长度、分隔符或校验规则组包。这和前面进程日志、网络分片的思路相通。

媒体播放通常要同时保存 `QMediaPlayer` 和 `QAudioOutput` 对象；有类能导入，不代表系统具备所有编码格式的解码能力。发布时要在目标环境测试实际媒体文件。

OpenGL 不只是换一个控件，它要求理解图形管线、上下文和资源生命周期。只需要画简单图表或状态图时，先考虑 `QPainter` 或合适的现成绘图库。

打印和 PDF 输出也要区分。`QtPrintSupport` 管理打印设备与预览；`QtGui.QPdfWriter` 可以作为绘制 PDF 的输出设备。复杂排版仍需要明确的分页、字体与布局设计。

## 7. Widgets 和 QML/Qt Quick 怎么选

Widgets 适合控件密集的桌面工具，表格、树、菜单和对话框成熟；QML/Qt Quick 用声明式语言描述界面，适合动画、流畅过渡和触控交互较多的产品。

学习 QML 意味着同时学习另一种界面描述方式、属性绑定和 Python 与 QML 的交互边界。它不是“学完 Widgets 后必须升级到的高级版”。如果目标是实用桌面管理程序，Widgets 可以长期使用。

混合两种界面是可行的，但会增加对象生命周期、渲染和数据桥接的复杂度。先有明确需求，再决定是否混合。

1. 为“串口温度仪界面”“批量视频工具”“任务管理器”各选择最少的一组模块，并说明原因。

3. 在事务中增加第二次插入并故意制造失败，确认第一条也没有被提交。
4. 从官方文档任选一个从未用过的类，写出所属模块、构造参数、关键方法、信号和最小实验。
5. 比较你的下一项需求使用 JSON、sqlite3 和 QtSql 的成本，做出书面选择。

自检：能否分清 Qt 模块和 PyQt 分发包？能否解释绑定参数与拼 SQL 的区别？新技术带来哪些依赖和验收工作？学会根据问题选工具，才算掌握了模块地图。
