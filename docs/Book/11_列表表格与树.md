# 第十一章　把多条数据组织给用户看

[返回阅读地图](00_阅读地图与学习方法.md) · [上一章：对象生命期与窗口通信](10_对象生命期与窗口通信.md) · [下一章：模型视图与代理](12_模型视图与代理.md)

一个输入框适合编辑一个值，十个输入框却不一定适合展示十条任务。当数据具有重复结构时，列表、表格和树能让用户更快地寻找、比较和选择。本章先从使用容易的“项目式控件”入手；下一章再把数据管理从界面中分离出来。

## 1. 按数据关系选择控件

| 数据关系 | 方便入门的控件 | 对应的模型视图控件 | 例子 |
| --- | --- | --- | --- |
| 一串同类项目 | `QListWidget` | `QListView` | 最近文件、任务名称 |
| 每条记录有相同字段 | `QTableWidget` | `QTableView` | 名称、优先级、完成状态 |
| 项目具有父子层级 | `QTreeWidget` | `QTreeView` | 文件夹、组织结构、分类 |

带 `Widget` 的这一组由你直接创建和操作项目对象，例如 `QTableWidgetItem`。带 `View` 的这一组主要负责显示，数据通过模型提供。项目式控件内部也使用模型，但它把许多细节包装起来了。

不要把“数据多”简单理解成“超过某个固定行数就必须换模型”。当同一份数据需要多个视图、严格校验、排序筛选、单元测试，或者需要与数据库同步时，模型视图通常更合适，即使记录并不多。

## 2. 一个可以独立运行的表格

以下是**完整程序**，可保存为自己的练习文件。它展示两个关键习惯：数据标识放在 `UserRole` 中，数字按数字保存。

```python
import sys

from PyQt6.QtCore import Qt
from PyQt6.QtWidgets import (
    QApplication, QAbstractItemView, QLabel, QTableWidget,
    QTableWidgetItem, QVBoxLayout, QWidget,
)


class Window(QWidget):
    def __init__(self):
        super().__init__()
        self.setWindowTitle("项目式表格")
        self.resize(520, 300)
        self.table = QTableWidget(3, 2)
        self.table.setHorizontalHeaderLabels(["任务", "优先级"])
        self.table.setSelectionBehavior(QAbstractItemView.SelectionBehavior.SelectRows)
        self.table.setSelectionMode(QAbstractItemView.SelectionMode.SingleSelection)
        self.table.setEditTriggers(QAbstractItemView.EditTrigger.NoEditTriggers)
        self.message = QLabel("请选择一条记录")

        records = [(101, "阅读文档", 2), (102, "练习布局", 10), (103, "整理笔记", 1)]
        self.table.setSortingEnabled(False)
        for row, (task_id, title, priority) in enumerate(records):
            name_item = QTableWidgetItem(title)
            name_item.setData(Qt.ItemDataRole.UserRole, task_id)
            number_item = QTableWidgetItem()
            number_item.setData(Qt.ItemDataRole.DisplayRole, priority)
            self.table.setItem(row, 0, name_item)
            self.table.setItem(row, 1, number_item)
        self.table.setSortingEnabled(True)
        self.table.itemSelectionChanged.connect(self.show_selection)

        layout = QVBoxLayout(self)
        layout.addWidget(self.table)
        layout.addWidget(self.message)

    def show_selection(self):
        rows = self.table.selectionModel().selectedRows()
        if not rows:
            self.message.setText("没有选中记录")
            return
        item = self.table.item(rows[0].row(), 0)
        task_id = item.data(Qt.ItemDataRole.UserRole)
        self.message.setText(f"选中的任务编号是 {task_id}")


if __name__ == "__main__":
    app = QApplication(sys.argv)
    window = Window()
    window.show()
    sys.exit(app.exec())
```

点击优先级表头排序，应该得到 1、2、10，而不是 1、10、2。然后选择不同记录，观察下方显示的是稳定任务编号，不是随排序变化的行号。

## 3. 项目、单元格与数据不是同一个东西

`QTableWidget(3, 2)` 建立三行两列，但并没有自动创建六个 `QTableWidgetItem`。如果某个位置尚未设置项目，`table.item(row, column)` 可能返回 `None`。读取文本前应该知道该位置已经初始化，或先判断是否为空。

`QTableWidgetItem` 保存的是一个单元格的内容、图标、对齐方式、可编辑标志以及附加数据。`setItem()` 把项目交给表格拥有。同一个项目不能同时放到两个单元格；需要复制内容或创建新的项目。`takeItem()` 则从表格取走项目并返回它，所有权随之转交。

示例中的 `UserRole` 是供应用保存自定义数据的角色。标题可能重复或修改，任务编号则用于识别记录。不要用“当前第 2 行”作为任务永久编号，因为排序、插入和删除都会改变行号。

数字排序还有一个小陷阱：`QTableWidgetItem("10")` 存的是文本，而 `setData(DisplayRole, 10)` 存的是整数。显示起来相似，排序的语义不同。数据类型应该反映业务含义。

填充表格时暂时关闭排序，是因为设置用于排序的那一列之后，当前行可能立刻移动；后续给其他列赋值就可能落到不同记录上。填充完成再开启排序，能避免这一类错位。

## 4. 选择、当前项、编辑是三个不同状态

“当前项”通常指键盘焦点所在的项目；“选中项”指被选择用于后续操作的项目。允许多选时，可以有多个选中项，但通常只有一个当前项。不要因为 `currentRow()` 有值，就认定用户选择了某一整行。

示例使用按行选择和单选，所以从 `selectionModel().selectedRows()` 可以得到完整选中行的索引。多选时，该方法返回多个索引，删除前应先收集行号，并按从大到小的顺序删除。否则删除第 1 行后，原来的第 2 行会变成新的第 1 行。

`NoEditTriggers` 禁用了用户通过界面开始编辑的入口，不是数据层的安全规则。代码仍然可以调用 `setText()`。如果一条业务规则要求“名称不能为空”，应在正式的数据模型或业务层校验，而不是仅仅靠禁止某个界面操作。

编辑表格时经常用 `itemChanged(item)` 或 `cellChanged(row, column)`。注意：代码主动修改项目也可能发出这些信号；在处理槽中再修改同一项目，可能导致重复触发。批量程序更新可以短暂使用 `QSignalBlocker` 屏蔽某个对象的信号，但仍要想清楚更新结束后如何刷新相关状态，不能把屏蔽信号当成通用修复。

## 5. 列表与树怎么对应到相同思想

列表的入门写法是 `list_widget.addItems(["草稿", "已完成"])`。需要附加编号时，先创建 `QListWidgetItem`，调用 `setData(UserRole, id)`，再加入列表。常用信号包括 `itemClicked(item)`、`currentRowChanged(row)`；清空或取消当前项后，当前行号可能是 -1。

树项目可以拥有子项目。以下是**片段**，假定已经创建 `tree = QTreeWidget()`，并导入 `QTreeWidgetItem`：

```python
tree.setHeaderLabels(["分类", "说明"])
group = QTreeWidgetItem(["学习资料", "父级"])
child = QTreeWidgetItem(["Qt 文档", "参考资料"])
group.addChild(child)
tree.addTopLevelItem(group)
tree.expandAll()
```

表格通过行列定位一个项目，树还要知道它属于哪个父项目。不要把整棵树中的“第 3 个节点”当成稳定位置。业务数据同样应该有自己的编号。小树可以 `expandAll()`，层级和数据规模较大时应按需展开和加载。

## 6. API 与练习

| API | 返回值或信号参数 | 注意点 |
| --- | --- | --- |
| `table.item(row, column)` | 项目对象或 `None` | 有行列不一定已有项目 |
| `item.data(role)` | 对应角色的数据 | 可见文本不等于全部数据 |
| `table.removeRow(row)` | 无业务返回值 | 后面的行会向前移动 |
| `selectedRows()` | 一组 `QModelIndex` | 与按行选择搭配使用更直观 |
| `itemSelectionChanged` | 无参数 | 在槽中读取当前选择 |
| `itemChanged(item)` | 变化的项目 | 程序修改也可能触发 |

1. 为表格增加“状态”列，要求排序后各列仍属于同一任务。先填满各列，再启用排序。
2. 改成多选并增加删除按钮。验收：排序后选择不相邻的两条记录，删除的正是选中记录；没有选择时不报错。
3. 用 `QTreeWidget` 表示“课程 → 章节”，给每个章节保存独立编号。验收：两个同名章节也能区分。
4. 解释为什么把大量按钮通过 `setCellWidget()` 塞进表格会增加开销。进一步思考：同一份任务数据若还要显示在统计页，维护两套项目对象有什么问题？这正是下一章要解决的事。
