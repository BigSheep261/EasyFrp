# 第 20 章：打包、发布与维护——让别人的电脑也能运行

[上一章：调试日志与测试](19_调试日志与测试.md) · [阅读地图](00_阅读地图与学习方法.md) · [下一章：扩展模块与技术选择](21_扩展模块与技术选择.md)

本章目标：把已经验证过的 PyQt6 程序打包为 Windows 应用，处理资源和配置路径，并建立基本的发布验收流程。打包不是修复源代码问题的办法；先确保源码运行正确，再逐步解决发布差异。

## 1. 打包到底做了什么

PyInstaller 收集 Python 解释器、程序代码、依赖库及必要资源，生成目标操作系统可运行的分发物。它不会把 Python 业务逻辑自动改写成独立的 C++ 程序，也不保证源代码无法被分析。

通常要在目标操作系统上构建对应平台的软件。Windows 构建产物不能直接当作 macOS 应用使用；不同架构也需要匹配环境。Qt 平台插件、图片格式插件及其他运行库是否被正确收集，需要通过实际运行确认。

`onedir` 把程序和依赖放进一个目录，容易检查缺失文件；`onefile` 生成单个启动文件，运行时通常要解压到临时位置，启动和路径行为更复杂。学习阶段先用 onedir，确认正确以后再评估是否需要 onefile。

## 2. 使用教材自己的虚拟环境

以下命令都从项目根目录执行，只使用 `docs/Book/.venv` 学习环境，不要求改动项目业务环境。若尚未创建，请先完成第 3 章。

```powershell
.\docs\Book\.venv\Scripts\python.exe -m pip install PyInstaller
.\docs\Book\.venv\Scripts\python.exe .\docs\Book\示例代码\第七课_后台任务.py
```

先确认源码的正常完成、取消、模拟失败和运行中关闭四条路径。这里选择第七课是因为它只使用 Python 和 PyQt6，且不需要外部网络、文件资源或子进程解释器。

记录当前依赖有助于复现。Windows PowerShell 的默认重定向编码可能不适合 requirements 文件，因此明确使用 UTF-8：

```powershell
.\docs\Book\.venv\Scripts\python.exe -m pip freeze | Set-Content -Encoding utf8 .\docs\Book\学习环境依赖.txt
```

冻结列表记录“这次环境实际装了什么”，还应在发布记录中写明 Python 版本、操作系统和构建命令。维护正式项目时，可以进一步区分直接依赖与完整锁定结果。

## 3. 先构建带控制台的目录版本

```powershell
New-Item -ItemType Directory -Force .\docs\Book\构建配置 | Out-Null
.\docs\Book\.venv\Scripts\python.exe -m PyInstaller --noconfirm --clean --onedir --console --name "后台任务演示" --distpath .\docs\Book\发布文件 --workpath .\docs\Book\构建缓存 --specpath .\docs\Book\构建配置 .\docs\Book\示例代码\第七课_后台任务.py
```

各参数的作用：`--onedir` 生成目录版；`--console` 保留终端便于观察异常；`--name` 指定应用名称；distpath 放最终分发物，workpath 放构建中间文件，specpath 放构建规格文件。`--noconfirm` 允许覆盖同名构建产物，因此不要把重要手工文件放进这些生成目录。

构建完成后，从终端运行：

```powershell
& ".\docs\Book\发布文件\后台任务演示\后台任务演示.exe"
```

把整个“后台任务演示”目录交给测试环境，不能只复制其中的 exe。确认控制台无异常、线程能结束之后，再生成不显示控制台的版本：

```powershell
.\docs\Book\.venv\Scripts\python.exe -m PyInstaller --noconfirm --clean --onedir --windowed --name "后台任务演示" --distpath .\docs\Book\发布文件 --workpath .\docs\Book\构建缓存 --specpath .\docs\Book\构建配置 .\docs\Book\示例代码\第七课_后台任务.py
```

`--windowed` 隐藏控制台后，用户无法依靠终端看到异常。正式程序要先加入文件日志和必要的错误提示。教材第七课把模拟错误打印到 stderr，适合控制台教学；准备正式无控制台发布时，应按上一章替换为可靠文件日志。

## 4. 三种路径不要混在一起

工作目录是“进程现在以哪里为相对路径起点”；资源目录是“随应用发布的图标、模板在哪”；用户数据目录是“用户可写的设置和数据应该存哪”。它们不一定相同。

不要假设用户总在源码目录打开程序。快捷方式、资源管理器双击和终端启动可能给出不同工作目录。随程序发布的只读资源，可基于模块的 `__file__` 定位，并在 PyInstaller 中按相同相对结构收集：

```python
from pathlib import Path

RESOURCE_DIR = Path(__file__).resolve().parent / "资源"
icon_path = RESOURCE_DIR / "应用图标.png"
```

这段片段假定“资源”与当前模块同目录。打包时可用当前版本支持的 `--add-data SOURCE:DEST` 语法或 `.spec` 文件的 `datas` 指定目标结构；以你安装版本的 `--help` 为准。Qt 的 `.qrc` 资源系统也可以把资源注册为 `:/...` 路径，减少运行时路径判断。

配置文件、日志和数据库应写进用户可写位置，不能默认写到 exe 旁边。应用安装在 `Program Files` 时普通用户可能没有写权限；onefile 临时解压目录也不适合持久数据。

```python
from pathlib import Path
from PyQt6.QtCore import QCoreApplication, QStandardPaths

QCoreApplication.setOrganizationName("学习示例")
QCoreApplication.setApplicationName("任务管理器")
data_dir = Path(QStandardPaths.writableLocation(
    QStandardPaths.StandardLocation.AppLocalDataLocation
))
data_dir.mkdir(parents=True, exist_ok=True)
config_path = data_dir / "配置.json"
```

组织名和应用名应保持稳定，否则新版本可能去另一个目录找数据。Windows 上 AppLocalDataLocation 通常位于用户本地应用数据目录；具体路径由系统和 Qt 决定，不要自己硬编码用户名。

## 5. 找不到资源、插件或依赖时怎么排查

先运行 console 版本，保存完整错误。缺少自己项目动态导入的模块时，检查收集规则和 hidden imports；缺少图片先打印实际资源路径；提示平台插件加载失败时，检查 Qt 插件是否收集、架构是否一致以及环境变量是否被其他 Qt 安装污染。

不要不看错误就复制整个 Python 环境，或者从陌生网页下载某个 DLL 放进去。这样可能暂时掩盖症状，却让版本与依赖关系更难追踪。每次只改变一个明确条件，再重建验证。

代码中依赖系统命令、外部 exe、字体和设备驱动时，也要逐项说明是否随程序分发、是否由用户安装。PyInstaller 不会自动解决所有应用外部依赖。

## 6. 干净环境验收

开发机安装了许多依赖，很容易掩盖遗漏。至少找一个没有你的源码目录和开发虚拟环境的普通用户环境，验证：

1. 从含中文和空格的路径启动，窗口、图标和文本显示正常。
2. 不以管理员运行，设置、日志和数据仍可写入。
3. 覆盖正常完成、取消、输入错误、保存失败和运行中关闭。
4. 断网时网络功能给出可理解的提示，其余功能仍可使用。
5. 重启应用后数据存在，升级版本后旧数据仍能读取。
6. 在常见缩放比例和分辨率下检查布局，错误日志能被用户找到。

发布物还应附上版本号、使用说明、已知限制和第三方许可证。代码签名、安装器和自动更新可以后续逐步增加；更新下载和替换文件本身也需要可靠设计，不要用简单覆盖正在运行 exe 的方法处理。

## 7. 许可证不是“装得上就一定能这样发布”

PyQt6 通常采用 GPL v3 与商业许可证双重授权，而不是 LGPL。使用 GPL 路线分发应用时，需要满足适用的 GPL 义务；如果计划发布不按 GPL 兼容方式提供的专有应用，需要评估合适的商业许可，不能因为程序免费或使用 Python 就跳过这一步。

Qt 底层库、附加模块以及打包进来的其他依赖也有各自许可证。PySide6 的授权路线与 PyQt6 不同，但换绑定也不意味着所有附加模块和分发义务都自动消失。

实际发布前查阅 [Riverbank 的 PyQt 许可说明](https://www.riverbankcomputing.com/software/pyqt/intro) 与 [Qt 许可说明](https://www.qt.io/licensing/)，以具体版本和分发方式为准。学习阶段先知道这是一项产品决策；商业发布时再根据实际项目确认合规方案。

## 8. 练习与自检

1. 先生成 console 目录版，再生成 windowed 版，记录二者排错体验差异。
2. 添加一个图标资源，分别验证源码启动、换工作目录启动和打包运行。
3. 把配置与日志迁到 `QStandardPaths` 返回的目录，确认升级程序不覆盖数据。
4. 编写一页发布验收记录，标明系统、Python、PyQt、Qt、PyInstaller 版本。
5. 让另一位使用者只根据说明运行你的程序，记录他在哪一步需要解释。

自检：你能解释为什么只拷贝 exe 不够吗？资源与可写数据分放在哪里？没有终端如何查错？干净机器验证了什么？这些问题回答清楚，打包才真正进入“可以交付”的阶段。
