# 第 4 章：窗口、控件与对象

> 前置知识：已经运行第一课。目标：理解窗口也是对象，选择合适的窗口基类，知道属性、方法、父对象和 Python 引用各解决什么问题。

## 4.1 所有看得见的东西都叫窗口吗

Qt Widgets 中的按钮、输入框和标签都属于控件，英文是 widget。`QWidget` 是它们的重要基类，提供位置、尺寸、显示、隐藏、焦点、绘制等能力。

一个没有父控件的普通 `QWidget` 通常成为独立的顶层窗口；有父控件的 `QWidget` 通常显示在父控件里面。注意“通常”：窗口标志等设置可以影响行为，这里先学习最常用情况。

这意味着窗口与里面的控件有共同基础。`QPushButton` 也能调用 `resize()`、`setEnabled()`、`hide()`，因为它继承了 `QWidget` 的能力。但“可以调用”不等于“应该自己设置位置”；加入布局以后，位置和尺寸通常交给布局计算。

常见继承关系可以简化为：

```text
QObject
└── QWidget
    ├── QLabel
    ├── QLineEdit
    ├── QAbstractButton
    │   └── QPushButton
    ├── QDialog
    └── QMainWindow
```

这不是完整类图，只展示本阶段要认识的部分。`QObject` 提供对象树、信号槽、事件等基础，本身不一定可见。计时器 `QTimer` 是 QObject，但不是 QWidget，因此没有窗口外观。

## 4.2 QWidget、QDialog、QMainWindow 怎样选

| 类 | 常见用途 | 你应记住的结构 |
| --- | --- | --- |
| `QWidget` | 简单独立窗口、复用面板、页面组件 | 安装自己的布局，放入子控件 |
| `QDialog` | 编辑资料、设置、确认等短期交互 | 有接受/拒绝的对话结果语义 |
| `QMainWindow` | 带菜单、工具栏、状态栏的主程序 | 使用中央控件，另有专门的菜单等区域 |

小工具只需要几个输入框时，继承 `QWidget` 完全合理。需要菜单和状态栏时，`QMainWindow` 提供现成组织方式。不要因为名字叫“主窗口”，就以为所有应用只能用 `QMainWindow`。

`QMainWindow` 自己已有特殊布局。不能像普通 QWidget 一样直接对它安装 `QVBoxLayout(self)`。正确做法是创建中央控件，把普通布局放到中央控件，再调用 `setCentralWidget()`。完整用法在第 8 章。

`QDialog` 是否阻止用户操作其他窗口，由其模态设置及打开方式决定，不是名字一叫对话框就必然阻塞。第 8 章会区分 `show()`、`open()` 与 `exec()`。

## 4.3 创建、配置、排列、连接

组织初始化代码时，可以遵循这个顺序：

1. 创建控件，并保存以后还需要访问的控件引用。
2. 设置默认文字、范围、提示等属性。
3. 使用布局排列控件。
4. 连接信号与处理方法。
5. 按初始数据刷新一次界面状态。

下面是放在窗口 `__init__` 里的片段，前提是已导入 `QLabel`、`QPushButton`、`QVBoxLayout`，并调用过 `super().__init__()`：

```python
self.status_label = QLabel("还没有开始")
self.start_button = QPushButton("开始")
self.start_button.setEnabled(True)

layout = QVBoxLayout(self)
layout.addWidget(self.status_label)
layout.addWidget(self.start_button)

self.start_button.clicked.connect(self.start_work)
```

同一个类中还需要定义 `start_work(self)`，例如把标签改为“已开始”。这些步骤不必全写在一个超长构造方法里；规模变大后可以拆成 `_create_widgets()`、`_build_layout()`、`_connect_signals()` 等方法。现在先保证自己知道每行是在创建东西、改状态，还是登记回调。

## 4.4 方法名称里藏着规律

Qt 有大量 `setXxx()` 与 `xxx()` 成对出现的方法。前者修改属性，后者读取属性。例如 `setText("你好")` 改文字，`text()` 读取文字。

| 常用方法 | 参数与返回值 | 作用与边界 |
| --- | --- | --- |
| `setWindowTitle(title)` | `str → None` | 修改顶层窗口标题 |
| `resize(w, h)` | 两个 `int → None` | 请求尺寸；布局和尺寸约束也会参与 |
| `setMinimumSize(w, h)` | 两个 `int → None` | 设置用户不能缩得更小的尺寸 |
| `show()` / `hide()` | 无参，返回 `None` | 改变显示状态，不等于销毁对象 |
| `setEnabled(enabled)` | `bool → None` | 控制可交互状态，禁用父控件也会影响子控件 |
| `isEnabled()` | 返回 `bool` | 查询控件的有效启用状态 |
| `setVisible(visible)` | `bool → None` | 显示或隐藏控件 |
| `isVisible()` | 返回 `bool` | 查询可见状态；父控件不可见也会影响结果 |
| `setToolTip(text)` | `str → None` | 鼠标停留时显示简短提示 |
| `setFocus()` | 返回 `None` | 请求键盘焦点，需要合适的可见/启用条件 |
| `setObjectName(name)` | `str → None` | 为对象命名，供查找、样式等使用 |
| `close()` | 返回 `bool` | 请求关闭；关闭事件可以接受或拒绝 |

这些是简化的常用调用形式，部分方法还有其他重载。读文档看到多种签名，表示同名方法可以接收不同类型或数量的参数。例如 `resize()` 也可以接收一个 `QSize`。

不要写 `label.text = "完成"` 来修改标签文字。这只是试图给 Python 对象增加或覆盖一个名为 `text` 的属性，可能遮蔽原方法，也不会按你期待的方式更新 Qt 文本。应调用 `label.setText("完成")`。

同样，不要把 `self.save_button`、`objectName` 和按钮上的文字当成同一个名字。前者是 Python 属性名，`objectName` 是 Qt 对象的标识属性，`text()` 是给用户看的内容，各有用途。

## 4.5 父子关系和 Python 引用

下面是概念片段：

```python
parent = QWidget()
button = QPushButton("保存", parent)
```

这里 `parent` 是按钮的 Qt 父控件。这带来至少两件事：按钮属于父控件的界面范围；父对象真正销毁时，它拥有的子对象通常一起销毁。

Python 的 `self.button = button` 则保存了一个 Python 引用，让其他方法能够访问这个按钮。**引用负责让 Python 代码找得到对象；Qt 的父子关系负责对象所有权等框架行为。** 两套机制会相互配合，但不是同一件事。

第一课没有给 QLabel 显式传父控件，而是把它加入安装到窗口上的布局。布局会把控件归到所属窗口的控件树里。布局本身管理几何位置，不能简单说成“布局是所有控件的可见父控件”。实际父控件是对应的 QWidget。

如果父窗口已经被真正删除，即使还留着子控件的 Python 引用，也不能继续调用底层已被删除的 Qt 对象。反过来，创建没有 Qt 父对象的独立窗口却不保存 Python 引用，也可能导致它过早消失。完整生命周期策略见第 10 章，现在先坚持“谁创建独立窗口，谁保存它的引用”。

## 4.6 隐藏、关闭和删除不同

`hide()` 暂时不显示，对象仍可继续使用。`close()` 会发送关闭事件，事件被接受后窗口通常隐藏；默认情况下，不能一概说它已经删除。设置了 `Qt.WidgetAttribute.WA_DeleteOnClose` 的窗口，关闭后会被删除，生命周期就不同。

应用默认会在最后一个相关顶层窗口关闭后退出事件循环。于是你观察到“窗口关闭，程序结束”，并不代表 `close()` 对所有控件永远等于“立刻释放”。第 10 章会用例子验证这些区别。

初学阶段先不要凭感觉随处调用删除方法。若一个按钮暂时不能使用，通常应 `setEnabled(False)`；一个区域暂时不展示，通常应 `hide()`；一条数据从列表删除，则还涉及数据本身和对应视图，不能只隐藏一个控件就算完成业务删除。

## 4.7 把窗口当成有状态的对象

第一课的 `click_count` 是状态，标签只是这个状态的展示。按钮被点击以后：

```text
用户点击 → say_hello → click_count 增加 → 标签文字刷新
```

如果你只让标签显示“已经点击 3 次”，却没有更新 `click_count`，下一次计算就会出错。因此应思考：真实数据保存在什么地方？哪段方法改变它？哪些显示需要一起刷新？

小程序可以把简单状态放在窗口中，后面再分离模型和业务层。现在没有必要一开始就建立几十个文件，但要避免把标签文字当成唯一数据源：为了获取计数再从“已经点击 3 次”中切割字符串，是容易出错的设计。

## 4.8 本章练习与自检

1. 在第一课中增加 `setToolTip()`，悬停按钮观察；再给按钮设置对象名，检查按钮显示文字是否因此改变。
2. 增加一个复选框，用其状态控制按钮 `setEnabled()`，观察禁用后的样式和输入表现。信号连接可以先查下一章。
3. 画出第一课的控件树：窗口、标签、按钮分别是谁的子控件？把布局单独标为排列规则。
4. 把点击次数限制到 5，达到上限后禁用按钮，再提供“重置”操作。要求重置同时更新数据、标签和启用状态。
5. 独立描述一个“设置面板”应该继承 QWidget 还是 QMainWindow，说明你的选择与实际功能有什么关系。

自检：能否解释 `self.button` 与 Qt 父对象的不同？能否说清 `setText()` 和 `text()` 各返回什么？能否区分禁用、隐藏、关闭和删除？本章不要求记住对象删除的全部细节，但不能把这四件事混为一谈。
